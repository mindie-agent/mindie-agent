# Harness 边界与生命周期

当前合同，2026-10-09。继承[九条设计原则](design-principles.md)，服务于[架构](architecture.md)定义的普通原生任务；实现和真实验收见[统一实施进度](implementation-status.md)。本文替代此前可选摘要摘录、每任务手动激活和默认业务总时限的约定。旧版本证据保留在历史记录，不作为本合同已实现的证明。

## 职责与普通使用

适配器拥有原生任务身份、命名 transcript 的可信来源、公开记录解析、该端模型调用，以及插件安装和版本切换。共享知识组件拥有中立的授权/游标/队列、脱敏、必要索引、检索、发布回执和恢复。remote-dev 拥有远端执行和产物；diagnostics 拥有有界本地记录与独立选择的故障上报。协调工具和设备观测工具只在实际需要时介入。

不新增统一 Harness、领域路由器、第二套发布数据库或通用任务平台。用户继续使用业务仓库与原生任务。可选知识读取及远端能力不依赖采集激活；查询、反馈、状态和收尾都不是日常前置步骤。Skill 提供入口信息和适用方法，不规定每个任务的研究路线。

## 身份、选择与范围

贡献 choice、公开仓库、账号和项目范围是现有持久配置；新任务、重启、升级不产生第二次授权。缺配置、范围不符、明确停用及读取损坏分别报告。已有 read-only/later 拒绝意图继续作为停用处理，不能升级为公开贡献。独立故障上报的选择不被贡献配置代替。

首次配置只询问确实缺失的信息，复用已有明确选择；不新增“只读”或“稍后”产品档位。后续配置支持增量修改，无需重装、手改 JSON 或改动无关插件。安装成功、选择已保存、任务绑定与实际采集/贡献回执分别报告。

每个原生 task/fork 的材料归属来自可信 host 身份与 transcript 头。不能猜测最新会话、相同 cwd、相似输入或其他任务的时间戳。采集下界来自有效授权、task/fork 创建时间及明确关停窗口；内部建库、绑定或首次 Stop 的时间不是新的授权下界。只读当前明确命名的 transcript，不自动发现历史。显式历史导入复用同一投影、脱敏、索引和包协议。

每次外部写均重新读取这些现有授权。撤销阻止未发送动作；已经确认的 push 与未创建的 PR 分开记录。写入回执丢失必须保留 unknown 及原身份，先只读核对，不能当作未发送重试。重开仅承接其后获准材料，不补扫关闭期间的对话。

## 正文与模型

Codex 保留有序的用户输入、助手公开进展和最终回答；排除工具载荷、隐藏推理、注入指令和原生重复事件。机械投影不做语义缩写或首尾截取。Gitleaks 与固定隐私规则在正文、模型输入和发布之前执行。规则不能判定专有业务含义是否可公开，因此不能替代已有项目授权。

完整脱敏正文保存为不可变有序 Markdown 块，游标与有效元数据一起提交。LangMem 通过适配器的原生小模型，为全部新块生成标题/检索摘要及短导航；它不能改正文。每次只处理有界的新块和短导航，长任务继续推进到全部获准内容，不用任务总量阈值丢弃后半段。索引是公开打包的必要步骤，失败保留正文并报告未完成，不能用摘录冒充索引完成。

Codex 内部模型策略属于适配器，不继承业务任务强度，也不增加用户设置。已返回结果和 usage 先保存再本地应用；本地应用失败复用原结果。已提交但结果未知、已失败的模型输入不自动再次付费。查询、同步、包校验和发布不调用整理模型。Kimi 与 Claude Code 需要独立实现并验收自己的原生 worker。

## 操作寿命与错误

任务授权、一次工具操作、MCP 连接、本地进程树与远端持久 job 有不同寿命。默认无业务总执行时限，只有调用者明确要求的期限才交给执行者。安静或运行很久不证明失败；进程句柄、EOF、SSH 连接健康、所有者退出和明确错误决定是否继续。前台等待窗口返回原操作身份，不重新提交。设备租约的心跳与 fencing 保护资源归属，不能被当作业务最长时长。

取消只作用于本次拥有的进程树；明确设计为独立所有者的后台服务与远端持久 job 不随短启动器退出而误杀。已知成功或失败、未提交、外部结果未知分别表示。日志、账本、清理失败不能覆盖已知业务结果和主错误，必须带上剩余失败阶段、原操作身份与必要定位信息。

Stop 只持久准入并通知既有 owner，协议输出保持中性，不要求业务模型续跑。后台必要阶段的故障进入有界 Agent 诊断，在下一次自然能力调用中送达；只有日志或后台状态不算送达。解释器或脚本启动失败无法进入运行时诊断，包装层须向宿主提供有界 stderr 错误，保留完成情况未确认且不重放的事实。没有后续调用时保持未交付事实，不能写成成功。用户答复只需要反映其实际目标的结果和直接限制，不增加 MindIE 运维流程。

## 权威状态、恢复与回收

Markdown 是当前正文权威。SQLite 保存必要游标、队列、授权/身份关联与外部操作结果；ReMe 是可重建派生索引。缺损的权威库不能按首次使用建立空库，不能再拿空 snapshot 删除正文、尝试历史或 unknown 回执。初始化要先区分真正新状态与已有状态，校验必要表/字段/版本；创建意图中断也不能自动变成第二次首次使用。

所有权标记只说明初始化和版本归属，不复制业务数据，也不负责重建主账本。损坏阻止变更并保留资料，准确错误交给调用者。只有已知有效权威才可驱动派生索引重建或垃圾回收。事务中先完整验证候选再切换 current，坏末尾不得留下已宣称成功的半个语料库。

只保留当前有效正文和必要未决发送材料，不维护正文历史副本。收到精确提交回执后按当前发布/同步合同回收 frozen payload；新观察仍可追加，不能清掉未提交部分。当前远端 head/main 的独立修改必须核对；被拒绝、撤下或冲突的内容不自动复活。历史引用保持其字面身份，不把当前内容冒充旧版本。

## 升级与服务交接

适配器提交、唯一 runtime pins 与 product contract 共同指定一套产品组合；内容仓声明 schema、validator 和 Bot 规则。候选在自己的解释器中验证自身接口与实际安装包，旧更新器不 import 新版私有 API。普通内容更新沿用同一合同；合同变化需要匹配的组合。

各仓库达到发布标准并声明正常版本号之前，允许持续破坏性格式更新。正式版本候选必须声明一致的知识和远端回执发布边界；同格式升级保留状态，不兼容的已发布格式需要明确迁移，否则在退休旧运行时前拒绝。后续开发构建也不能解除已有正式状态的保护。详细合同见[发布前运行时设计](prerelease-runtime-design-2026-10-05.md)。

选中完整 generation 与取得 OS 使用租约在同一切换锁内完成。调用持续持有租约；回收保留 current、候选、未完成事务和活跃引用。宿主仍可能使用、但归属不明的路径保留并报告，不能猜 TTL。稳定管理入口调度当前选中版本，不能在重分派失败后悄悄运行旧副本。

知识组件提供同一个服务停用/恢复边界：在启动锁内针对精确配置指纹停止旧 generation 接收新工作，阻止已经 spawn 但迟到的旧 wake。实际业务忙则推迟切换；idle 授权或 unknown PR 回执本身不算忙。更新器不得仅凭暂时没有 endpoint/consumer lock 推断不存在启动中的服务。回滚只恢复相应指纹，保留确实停止过服务及后续恢复失败的事实。

恢复使用选定 Harness profile 和已有模型来源，不能用进程 ready 冒充模型可用。安装文件、宿主已加载定义、Hook 信任是不同事实；遵循宿主原生信任机制。更新中的网络故障经已有调度器持久退避继续，不因三次失败永久封禁正常版本。未知写入不自动重放；已知配置/内容/兼容错误立即可见。

## 验收边界

按最终组合验证首轮自动关联、fork/兄弟任务隔离、撤权、长静默、所有者退出、断连、已知结果后记录失败、缺库保留正文、未决副作用恢复和升级后原 job 可控。核对真实调用者收到的结果及副作用，不以内部 flag、进程存活或测试数代替。

组件测试、原生安装/Stop/MCP、实际 SSH/NPU、公开 PR/Bot 和新任务复用分别记录提交与证据。本轮开发样本、测试等待时间或模型预算不是产品门槛。历史结果可按其版本和适用范围复用，不要求每次重复全量验收，也不将旧证据写为当前版本已通过。
