# Harness 边界、首次配置与轻量本地状态

2026-09-21：本文是实施约定，不表示实现或验收已经完成。Codex、Kimi 与 Claude Code 三个独立适配器共同检验边界；旧领域 Skill 暂不迁移，profiling 分析继续跳过。真实完成情况统一记录在[实施进度](implementation-status.md)。

本轮实现继承 VAWS 的[九条设计原则](design-principles.md)，以完成真实任务的总成本为首要取舍。本文中的身份绑定、超时、去重和恢复是针对实际故障的机制，不构成额外的每任务流程；分仓也不意味着重复建设共享能力。

## 组件归属

| 组件 | 负责 | 不承担 |
| --- | --- | --- |
| Codex / Kimi / Claude Code 适配器 | 原生任务身份、显式入口、首次配置交互、Hook 翻译、公开记录解析、该端模型调用、插件安装与版本切换 | 另写一套知识库、贡献发布或修订协议 |
| 共享知识组件 | 中立的授权记录、增量游标、整理预算、脱敏、检索、贡献回执与恢复、确认提交后的清理 | 读取 Codex 私有租约表、猜测原生任务身份、硬编码某端 transcript 格式 |
| remote-dev | 远端文件、命令、作业归属、取消与产物 | 自动激活知识或采集 |
| GitHub + 现有 Grok Bot | 可共享正文的持久版本、审阅、合并、纠错与下库 | 保存原始 transcript 或成为在线查询服务 |

共享接口只承载确实需要的身份、授权与有界材料；不新增服务、统一 Harness 或通用调度框架。每个适配器可以有自己的薄入口，但同一项授权/配置规则不能分别维护相冲突的解释。

## 授权、执行、更新分开

用户显式启用的对象是当前原生任务。它的知识授权持续到明确停用、故障暂停或真正的范围变更；不会因为满 24 小时或插件目录换了版本而失效。Fork/新任务有自己的身份，不能继承另一任务的采集权限。

已授权不代表正在执行。实际调用、整理和提交各自有超时与活动记录；更新在这些操作空闲时切换完整版本。一次调用使用同一个已提交版本的脚本、解释器和依赖。远端作业的寿命独立于本地调用和插件更新，仍由原任务通过既有作业句柄查看或停止。

等待核对的旧 PR 回执不是正在执行的提交，不能让它永久阻塞升级。是否空闲由执行方原子地判断并停止接收新工作，不能靠“先查状态，再停止”的两步猜测。这个机制防止实际调用被版本切换打断，不增加用户操作。

更新器若确实停止了原本存活的知识服务，就在同一有界事务内完成服务交接：确认旧端点退出，安装或回滚确定后，在仍有有效显式授权的情况下，用实际选定版本恢复一次。更新前没有服务时不主动创建；恢复失败必须保留诊断，不能在后续同版本检查中抹成成功。Stop 仍只通知现有服务，不承担启动或补救。此前跨更新后先查询知识会间接启动服务，因此验收还须覆盖更新后仅使用远端工具、随后触发 Stop 的任务。

服务交接沿用明确选定的宿主配置及已有模型来源。系统定时任务不一定继承原任务的临时环境，不能仅凭服务就绪推定后续整理器能使用原账号和模型。按宿主读取已有明确持久配置，继续隔离整理器的 Hook、工具和 MCP；缺少所需配置时如实报错，不猜测或切换其他账号。

宿主已加载的 Skill/MCP 定义与磁盘安装状态分别报告。已有调用入口和必要回退版本不能在被使用时删除。宿主要求新的 Hook 信任时遵循其原生机制。

## 安装后或首次显式调用时配置

安装可在交互模式下配置；否则由首次显式调用入口检查配置。向用户简短说明推荐的社区贡献功能，以及公开内容、目标账号/仓库和项目范围，再提供选择：

- 开启当前项目的社区贡献（推荐）；
- 只使用知识和工具，不贡献；
- 稍后配置。

推荐不等于默认同意。选择不贡献或稍后配置，不妨碍正常检索、同步和远端工具，也不生成采集草稿。已经作出选择后不在每轮重复询问；用户可通过同一入口改配置。仅查看状态不启动知识服务或模型。

安装后配置必须支持增量更新现有 MindIE 配置，不要求重装或手改 JSON，不修改无关插件与用户配置。社区贡献中途关闭时取消未发工作；重开只授权此后材料。

## 本地只保留工作所需状态

GitHub 已确认接收 PR/更新且 head 与提交一致后，远端分支成为该版本正文的持久来源。可清理已提交版本的本地草稿正文、冗余历史、采集摘要和暂存文件，不必等到合并。尚有更新的未提交观察时，不能顺带清掉它。

本地保留最小的条目身份、摘要/续写线索、内容哈希、PR/head/path 回执，以及防重复所需的授权、游标和尝试记录。之后出现新观察时，按需有界读取先前已提交的准确正文再更新；不能只用新增段落覆盖全文，也不能覆盖维护者修正或重新发布已下库内容。

条目的最后一次确认回执不能随下一批其他条目或反馈覆盖。例如先提交 A，再提交 B，之后补充 A，仍应能找到 A 的准确前文；不需要因此保存 A 的本地正文历史。

超时后提交结果未知，不算确认提交；此时保留恢复所需材料。显式恢复先查原分支/PR，更新共享发布记录与本地 outbox，再决定后续动作。确定失败的提交可以显式再提交原材料，无需重新整理或调用模型。恢复不能重置采集边界或重放已失败的模型输入。

公开知识的 Git 缓存和检索索引可以重建。关闭贡献时，只需消费缓存及轻量工具状态，不维护采集正文档案。实现可以使用小型 SQLite 文件做事务和索引；重点是删除冗余内容和重复职责，不把 SQLite 换成同样复杂的 JSON 数据库。

## 防护保留在对应操作上

显式激活和贡献范围控制准入；任务身份控制读写归属；字节/时间限制控制单次资源使用；已尝试记录与写入核对防重复。失败暂停与明确恢复仍然存在。Hook 必须正常结束，不能要求业务模型继续回复。

各端原生能力分别验证。若某端 MCP 缺少任务元数据，需要有原生事件支持的明确绑定；不能用最新会话、工作目录或相同参数猜测。宿主自动重发也不能造成重复执行。没有足够身份依据时给出诊断并拒绝该操作。remote-dev 中表示作业的 session_id 参数不属于原生任务凭据，适配器不能因同名而一律拒绝。

## 验收重点

检查真实长任务接续、闲置任务与更新并存、运行中调用对更新的互斥、更新后原作业可控制、首次选择与后续配置、未知提交的恢复，以及提交后清理和同任务后续补充。分别记录组件检查、原生事件、真实 PR 和新任务消费证据。

Codex 模型验收继续使用 gpt-5.6-luna / max；用户已明确允许 Kimi 原生验收使用该端已配置的 K3 / max。Kimi 适配器独立放在 `mindie-agent-kimi` 仓库。不为了通过验收反复启动任务，也不把本轮开发截止时间或样本数量写成产品配额。

Claude Code 适配器独立放在 `mindie-agent-cc`，通过本地 Claude Code 原生入口验收；实际配置的模型必须如实记录。子代理负责该端实现协调和原生证据，主任务负责共同设计、跨端审查、进度和最终验收结论。例行取舍优先遵守九条原则，不新增每步审批。
