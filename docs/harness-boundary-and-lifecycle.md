# 宿主边界与任务生命周期（Harness Boundary & Lifecycle）

## 1. 宿主插件与共享组件如何分工？

MindIE Agent 不另建一套封闭的“大一统对话平台”，而是直接融入开发者现有的宿主 CLI。各模块各司其职：

| 层级 / 模块 | 负责什么 | 不做什么 |
| --- | --- | --- |
| **宿主原生插件管理器** | 插件包的下载、安装与已安装版本记录 | 不代替 MindIE 做跨宿主兼容性筛选 |
| **宿主插件适配器**（`mindie-agent-cc` / `-codex` / `-kimi`） | 识别宿主原生任务身份、定位可信 Transcript、提取公开对话、调用宿主原生轻量小模型、提供发布清单与锁定依赖（`uv.lock`） | 不自己维护第二套知识数据库或重复的进程守护状态机 |
| **共享知识引擎**（`knowledge`） | 管理授权与增量游标、执行确定性隐私脱敏、协调分块目录生成、提供本地/社区双层检索、处理 PR 发布回执与故障恢复 | 不直接耦合特定宿主的私有目录结构，也不靠猜测目录或时间戳来认领任务 |
| **远端开发与诊断组件**（`remote-dev` / `diagnostics`） | 独立提供 SSH 远端文件/长作业执行能力，以及有界本地日志与独立授权的故障上报 | 不依赖经验采集是否开启，也不截断用户远端作业的正常输出 |

日常开发中：
- **手动触发 `/mindie-agent`**：需要昇腾领域知识、历史排障经验与 Skill 引导时，直接输入 `/mindie-agent <问题描述>`（或 `$mindie-agent`）按需唤醒；
- **默认触发 `remote-dev`**：远端 SSH 与容器执行工具默认随时就绪，日常对话中直接描述远端机器或容器操作即可自动触发，不依赖经验采集是否开启。

## 2. 任务身份、用户授权与采集范围

### 2.1 授权一次配置，跨升级持久有效
- **持久化用户设置**：是否开启经验贡献、目标公开知识库、GitHub 账号与授权项目范围都保存在用户的持久化配置中，与插件代码版本解耦。
- **重装或升级不打扰**：开启新任务、重启终端或插件后台升级后，自动沿用已有授权设置。如果用户之前选择了“停用 / 暂不开启”，升级后依然保持停用，绝不会在后台静默开启上传。
- **增量修改**：首次引导只询问确实缺失的配置项；后续随时可以增量修改项目范围或开关状态，无需重装插件或手改底层 JSON。

### 2.2 精确的任务身份与采集时间边界
- **不靠猜测认领会话**：每个原生任务或子任务（Fork）的材料归属均来自宿主提供的可信会话 ID 与 Transcript 头部元数据，绝不靠“最新修改的文件”“相同的当前目录（`cwd`）”或“相似的提问内容”去瞎猜。
- **清晰的采集起点**：系统只采集用户开启授权后、在已授权项目范围内产生的新增对话；关闭授权会立即取消尚未发送的队列任务，重新开启后也只采集新产生的对话，不会回头把关闭期间的历史聊天记录补扫上传。

### 2.3 外部写入的 `unknown` 对账保护
- 每次执行外部写入（如推送分支或创建知识库 PR）前都会重新核对当前授权状态。
- 如果网络抖动导致写入回执丢失，该操作会被标记为 `unknown`（结果不确定）并保留原始操作 ID；系统在下次写入前必须先通过只读查询与远端仓库核对真实状态，绝不盲目当成“没发出去”而重复提交。

## 3. 对话正文提取与小模型索引边界

- **确定性提取公开对话**：仅保留有序的用户输入、助手公开进展和最终回答，剔除工具原始载荷、隐藏推理链（Reasoning）、系统注入指令和重复包装事件，不做掐头去尾的截断。
- **脱敏先行**：在写入磁盘、送给小模型或打包发布前，强制运行 Gitleaks 与确定性隐私脱敏规则。
- **小模型只写导航，不改正文**：适配器调用宿主自带的轻量小模型（配合 LangMem）为新增分块生成标题、检索摘要和短导航（`PACKAGE.md`）。小模型返回结果和 Token 用量会先落盘保存再应用到本地索引，一旦本地应用出错可直接复用已保存结果，绝不重复发起付费调用。

## 4. 操作寿命、取消信号与错误传递

1. **五类独立生命周期**：
   - 用户任务授权、单次工具调用、MCP 连接、本地辅助进程树、以及 `remote-dev` 远端持久后台作业拥有各自独立的生命周期。
   - **不设武断的全局业务超时**：耗时的远端编译或长算子测试只要连接与进程健康就继续运行，只有调用方显式传入的超时参数才会终止操作。
2. **精准取消，不误杀持久作业**：
   - 用户按取消（Interrupt）时，仅清理当前调用所拥有的进程树；独立运行的后台知识服务和通过 `remote-dev` 显式启动的远端持久作业不会因为一次短命令退出而被误杀。
   - *已知宿主限制说明*：在 `0.0.1` 版本中，OpenAI Codex CLI 在中断子代理（Subagent）时存在上游信号缺口，可能未向待处理的工具调用发送取消通知。MindIE Agent 如实记录该限制，不在插件内塞入高侵入性的私有杀进程轮询器；远端持久作业仍可通过 `remote-dev` 的 `job_cancel` 显式停止。
3. **跨平台进程树可靠回收**：
   - 后台摘要索引操作的进程树由平台原生原语兜底管理：Windows 使用命名 Job Object（`KILL_ON_JOB_CLOSE`），WSL 使用 `systemd` 临时用户服务（`KillMode=control-group`），macOS 使用轻量 `owner-pipe` 守护辅助进程，确保即使主控进程被强制 `SIGKILL` 也能干净回收所有子孙进程。详见[原生能力与系统机制复用](native-runtime-reuse.md)。

## 5. 本地权威状态保护与静默切换

- **Markdown 正文是唯一权威**：
  - 本地磁盘上的 Markdown 分块文件是唯一权威正文；SQLite 保存游标、队列与回执；ReMe 是可随时重建的内存派生索引。
  - 如果启动时发现 SQLite 数据库缺失或损坏，系统会明确报告故障并完整保留所有已有的 Markdown 正文和 `unknown` 回执，绝不会将其当作“全新安装”去清空知识目录。
- **单安装绑定与空闲原子切换**：
  - 插件运行环境通过 `uv sync --locked --no-editable` 安装在宿主易失缓存目录之外的稳定应用数据目录中，维护唯一的当前激活绑定（Canonical Binding）。
  - 后台静默更新在锁外准备好新版本环境后，等待当前服务无在途业务时获取排他锁，安全退役旧服务并原子切换绑定，无需用户手动 Reload。详见[版本兼容与无感更新](release-compatibility-and-update.md)。
