### 0.0.3 实测结果

固定任务集上的小样本实测结果（按宿主、模型与对照条件分别列出，不跨模型求平均）：`remote-dev`（G0 → G1）在 `quarot` 上实现 `3/3` 解出与 `1.025x` 交付提速，在 `dp2` 上与原生基线基本持平（`0.963x`）；`coordinator` 在双 Agent 并发抢占下实现零冲突协调；`knowledge` + Skills（G2/G3）提升了 `dp2` 与 `dsh` 的解题完成数并跑通跨任务经验复用，检索开销预计在 `0.0.3` 重点优化。

**实验条件**：**G0** 原生宿主；**G1** 接入 `remote-dev` 远端执行；**G2** 在 G1 上同时启用 `knowledge` 检索、随包 Skills 与显式检索提示；**G3** 在 G2 上将前置任务经验沉淀入库，供后续任务检索复用。

**组件实测场景**

- npu-top：3 轮硬件快照回放，每轮准确识别物理卡 24 张、进程归属 16/16；实机容器归属探测 3/3 通过。人工排查准确率：未测，耗时（秒）：未测（快照回放验证解析确定性，不等同于独立硬件样本）。
- coordinator：3 轮双 Agent 并发抢占实测，成功建立监听数 3 → 6，端口冲突 3 → 0，重复选卡 3 → 0（对比无协调的“先检查再绑定”基线）。
- diagnostics：3 轮本地 HTTP 上报场景中，9 次报错自动去重形成 3 条报告、3 次 POST；关键字段保留 3/3、隐私脱敏 3/3、关闭开关后立即停发 3/3。从报错到送达耗时 61.62-61.66 秒（含约 60 秒生产重试等待；本地测试不代表 GitHub 线上可用性或人工排障耗时）。
- profiler：3 轮确定性 SQLite 采集归因回放，Step 窗口对齐 3/3，慢卡（Attention）与慢链路（Comm）归因分离，显存归因达标 3/3，只读零库文件变更 3/3，分析耗时 5.42-7.57 ms（夹具回放验证归因准确性，不等同于新增实机采样）。
- sim：3 轮 A3 物理标定图预测与算子/子图边界筛查，Qwen2.5-7B 图预测确定性 3/3（TPOT 相对误差 4.14%），UB 溢出融合拦截 3/3，可行融合关键路径收益 5.0 us（基于公开标定锚点与算术夹具，不含客户端固定调度底噪）。
