# 0.1.12: Fix Windows Background Knowledge & Diagnostics Service Launchers

[中文](0.1.12.md) · [Product channel](../../channels/0.1.json)

This patch incorporates `mindie-knowledge v0.13.14` and `mindie-diagnostics v0.5.8` fixes for Windows Task Scheduler background launchers. Previously, Task Scheduler registration selected `pythonw.exe` based on file existence alone; when a Python distribution shipped a console-subsystem launcher shim under that filename, Windows flashed a console window before child-process `CREATE_NO_WINDOW` flags could take effect. Both new task registrations and recovered existing registrations now parse and verify the PE GUI subsystem (`IMAGE_SUBSYSTEM_WINDOWS_GUI`) prior to launch—failing fast with an explicit error on invalid binaries and allowing a clean retry once the environment is repaired.

## Behavior and validation

- **Windowless `knowledge` background execution**: Preserves virtual-environment identity, CLI arguments, graceful shutdown, and the no-replay guard on uncertain (`unknown`) starts, while adding Windows `CREATE_NO_WINDOW` flags to internal `ExperimentLedger` Git subprocess calls.
- **Pre-launch PE GUI gate in `diagnostics`**: Verifies the interpreter's PE GUI header before both initial task registration and explicit startup of existing scheduled tasks, rejecting console-subsystem, malformed, unreadable, or missing executables upfront.
- **Windows regression & interactive Task Scheduler verification**: Local Windows `knowledge` scope passed `204 passed, 3 skipped`, and the full `diagnostics` suite passed `329 passed, 15 skipped`. Live interactive Windows Task Scheduler desktop acceptance passed (`1 passed`), confirming service readiness, preserved venv and CLI arguments, zero visible windows or descendant `conhost.exe` processes, clean service stop, lock release, and temporary task cleanup.
- **Test environment & scope boundaries**: Verified on Windows `x86_64` with `uv 0.13.3` and `CPython 3.13.16`. Because hosted GitHub Actions runners lack an interactive desktop logon token, interactive window verification was executed on a local desktop session (without reinstalling the historical Issue `#115` environment or speculating on how the console-subsystem binary originated).
- **Related plugin hardening**: Equivalent scheduled-updater hardening for `mindie-agent-kimi` is tracked in [PR #68](https://github.com/mindie-agent/mindie-agent-kimi/pull/68); this product channel retains the published `Kimi v0.1.17` release rather than counting an unreleased commit as a formal plugin artifact.
- **Channel integrity & `R1–R6` verification**: All other components and plugins retain their pinned release tags and original benchmark receipts without relabeling historical runs as fresh measurements. Formal GitHub Releases, wheel/tarball contents, SHA256 checksums, exact-source benchmarks, and all `R1–R6` readiness gates passed verification.
