# 0.1.12: Fix Windows background knowledge and diagnostics service entries

[中文](0.1.12.md) · [Product channel](../../channels/0.1.json)

This combination records knowledge 0.13.14 and diagnostics 0.5.8 fixes for Windows scheduled entries. Previously, file existence was sufficient to select `pythonw.exe`; an executable bearing that name could actually be a console launcher outside existing subprocess `CREATE_NO_WINDOW` protection. New registrations and actual starts of recovered registrations now validate the real PE GUI subsystem. Invalid environments fail before launch and permit a normal retry after repair.

## Behavior and validation

- Knowledge preserves venv identity, arguments, normal stop and no replay of uncertain starts. Experiment-ledger Git calls now use the Windows no-window flag.
- Diagnostics checks the GUI entry before installation and explicit starts of existing registrations, rejecting console, malformed, unreadable or missing interpreters.
- Local Windows knowledge scope: 204 passed, 3 skipped. Complete local diagnostics suite: 329 passed, 15 skipped. Real interactive Windows Task Scheduler acceptance: 1 passed, verifying readiness, venv and arguments, no visible window or descendant `conhost.exe`, then normal stop, lock release and temporary task deletion.
- Measured on Windows x86_64, uv 0.13.3 and CPython 3.13.16. The original #115 environment was not reinstalled and the origin of its binary is not inferred. Hosted CI lacks an interactive login token; desktop acceptance runs separately.
- The equivalent Kimi updater-entry source fix is tracked in [PR #68](https://github.com/mindie-agent/mindie-agent-kimi/pull/68). This combination retains formal Kimi 0.1.17 and does not count the unpublished source change as a formal plugin artifact.
- Other components and plugins retain their exact formal tag sources and original benchmarks. Historical reports are not relabeled as new measurements. Formal Releases, package code, checksums, exact-source benchmarks and the R1–R6 gates are verified separately.
