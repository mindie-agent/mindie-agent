## 1. Google Antigravity 原生插件（`mindie-agent-agy v0.1.0`）与 7 大组件适配

`mindie-agent-agy` 以原生插件包（`plugins/mindie-agent/`）形式接入 Google Antigravity，并与全部 7 个共享运行时组件完成双向契约对齐：

1. **原生生命周期 Hook 与按会话知识租约门控**：
   - 通过 `plugin.json`、`hooks.json`（`SessionStart`、`PreInvocation`、`PreToolUse`、`Stop`）与 `mcp_config.json`（`mindie-remote-dev`、`mindie-tools`）挂载；
   - 公开 MCP 目录严格排除 `knowledge_*` 工具；仅当用户在当前会话（`conversationId`）显式输入 `/mindie-agent` 时，`PreInvocation` Hook 在 `admission.sqlite3` 中签发会话租约，由受门控的私有 `knowledge_cli.py` 调用本地 `mindie-knowledge` 检索、精读、反馈、C6 蒸馏与同步（子代理拥有独立 `conversationId`，天然隔离不继承父会话租约）。
2. **`remote-dev` 原生 Antigravity 工具别名映射**：
   - `mindie-remote-dev` 同时暴露 `remote-dev` 规范工具名（`remote_read`、`remote_write`、`remote_edit`、`remote_bash`、`remote_job` 等）与 Antigravity 原生工具别名（`remote_view_file`、`remote_view_file_outline`、`remote_view_code_item`、`remote_write_to_file`、`remote_replace_file_content`、`remote_multi_replace_file_content`、`remote_grep_search`、`remote_find_by_name`、`remote_list_dir`、`remote_run_command`、`remote_manage_task`），并双向映射 `StartLine`/`EndLine`、`WaitMsBeforeAsync` 与 `Action` 参数。
3. **`mindie-tools` 全组件桥接与 `AGY_CONVERSATION_ID` 会话透传**：
   - `mindie-tools` 常驻暴露 `mindie_status`、`diagnostics_status`、`diagnostics_bundle`、`coordinator`、`profiler`、`sim` 与 `npu_top`；
   - `mcp_server.py` 将已校验的 Antigravity `conversationId` 通过 `AGY_CONVERSATION_ID` 注入子进程环境，`mindie-coordinator` 的 `agent_session.py` 原生识别 `agy` / `antigravity` 客户端与 `AGY_CONVERSATION_ID`，实现多会话单 Die 显存租约（per-Die HBM lease）与容器绑定隔离。
4. **Antigravity Brain Transcript 双层脱敏采集**：
   - `agy_transcript.py` 自动从 `<appDataDir>/brain/<conversationId>/.system_generated/logs/transcript.jsonl` 提升读取 `transcript_full.jsonl`，严格剔除 `thinking` 思维链、`tool_calls` 与 `<ADDITIONAL_METADATA>` 包装块，交由 `mindie-knowledge` 的确定性规则（`r3`）与 Gitleaks 完成双层脱敏与分块入库。

## 2. 口语化真实报障语料与 `G0–G5` 全矩阵基准结果

评测前由 Codex 对 `mindie-bench` 测试系统进行了系统性防失真审计，修复了 `native_product.py` 跨任务经验隔离、`verifier.py` 宿主 `PYTHONPATH` 泄漏、`ssh_shim.py` 远端容器命令路由及 `diagnostics` 负向控制校验，并将全部 20 个 `tasks/zh-vague/` 提示词统一改写为**“一句话现象 + 原始报错堆栈或日志路径”**的真实开发者报障风格（并将原先需手写 3 处无堆栈跨文件改动的 `mrv2-dsa-prefill` 替换为具有明确 `IndexError` 报错位置的投机解码槽位容量题 `mtp-draft-slot-mapping-capacity-zh-vague`）。

1. **`G0 → G1 → G2`（48 场 L2 + 18 场 L3 昇腾真机 = 66 场端到端评测）**：
   - **L2 套件（8 任务 × 2 模型 × 3 档 = 48 场）**：
     - **DSH (`deepseek-flash`, `max`)**：`G0` `7/8 (87.5%)` → `G1` `7/8 (87.5%)` → **`G2` `8/8 (100.0%)`**（`G2` 平均耗时 **`72.3s`**，较 `G0` 的 `118.4s` 提速 **`1.64x`**；复杂 Profiler 归因任务从 `G0/G1` 50 轮耗尽失败跃升至 `G2` **19 轮 / `68.5s` 一次通过**）。
     - **Codex (`gpt-6.1-sol`, `xhigh`)**：`G0` `8/8 (100.0%)` → `G1` `8/8 (100.0%)` → **`G2` `8/8 (100.0%)`**（`G2` 平均耗时 **`121.0s`**，较 `G0` 的 `187.0s` 提速 **`1.55x`**；复杂 Profiler 归因任务从 `G0` `513.5s` 降至 `G2` **`133.9s`，提速 `3.84x`**）。
   - **L3 昇腾真机套件（3 任务 × 2 模型 × 3 档 = 18 场，A2 `173.125.1.2` `vllm-dev` 8×Ascend 910B）**：
     - DSH 与 Codex 在 `G0 / G1 / G2` 全部 **18/18 (`100%`)** 真实远端容器执行通过；`G2` 平均真机端到端耗时在 DSH 上从 `75.5s` 降至 **`50.9s`（`1.48x` 提速）**，在 Codex 上从 `104.3s` 降至 **`78.5s`（`1.33x` 提速）**。
2. **`G3`（跨任务经验蒸馏飞轮：Seed `rotary_dim=64` → Stop 采集 + C6 蒸馏 → Eval `rotary_dim=32` 黑盒 `.so`）**：
   - 在无源码黑盒 `.so` 算子属性迁移任务上，DSH 与 Codex 在无经验基线（`G0/G2`）下均因直接按 32 维切片触发底层 `.so` 契约校验失败（**`0/2, 0%`**）；经 Seed 任务自动采集并蒸馏出 `L2 SOP` 单元后，双宿主在 `G3` 均一次性通过（**`2/2, 100%`**，DSH `60.2s`，Codex `78.4s`）。
3. **`G4`（`mode="explore"` RSI 去偏开放探索 vs. `G0/G2` 常规模式）**：
   - 在 `dsv4-sparse-mla-qli-fusion-rsi-zh` 与 `triton-spatial-norm-dim-merge-rsi-zh` 两个算子融合与消融任务上，双宿主从 **`G0 (0/4, 0%) / G2 (0/4, 0%)` 跃升至 `G4 (4/4, 100%)`**。
4. **`G5`（5 阶段端到端演进飞轮 `Episode A → B → C → D → E`）**：
   - Codex (`gpt-6.1-sol`, `xhigh`) 在同一演化工作区内连续跑通 `Episode A`（SFA Cold Start，`62.4s`）→ `Episode B`（SFA Warm Reuse，`50.5s`，`-19.1%` 提速）→ `Episode C`（Black-Box RoPE 64 Seed，`113.0s`）→ `Episode D`（Black-Box RoPE 32 Flywheel Reuse，`113.4s`）→ `Episode E`（Compound Multi-Fault Synthesis，`70.2s`），实现 **`5/5 (100%)` 全链路闭环通过**。
