## 1. 根治自动更新阻塞的三道防线（防漏改 + 防漏检 + 发版前必检）

1. **防漏改（构建索引自动推进 `revision`）**：
   - `mindie-knowledge v0.13.8` 的 `build_routing_index()` 在重建 `index/routing-manifest.json` 与 `index/shard-topology.json` 时，自动比对已有清单与 `HEAD` 中各单元的 `content_sha256`；一旦检测到内容变更且 `revision` 未递增，自动将对应 `.md` 单元的 `revision` 推进为 `old_revision + 1`（`check=True` 模式下直接报错 `revision_not_advanced`）。
2. **防漏检（`publication_check` 跨版本单调性门禁 + 客户端修复容错）**：
   - `mindie_knowledge/publication_check.py` 新增 `_validate_graded_revision_advance()`，在 `validate(..., base_revision=...)` 校验中强制拒绝任何修改了 `content_sha256` 却未递增 `revision`、或降低 `revision` 的提交；
   - `GradedRepository.install_feed()` 将 `old.content_sha256 == unit.content_sha256` 时的校验放宽为允许 `unit.revision >= old.revision`，确保后续补充递增 `revision` 的修复提交不会阻塞曾同步过中间提交的客户端。
3. **发版前自动更新就绪必检项（`.github/scripts/check_auto_update_readiness.py`）**：
   - 新增发版前与 CI 必检脚本 `python3 .github/scripts/check_auto_update_readiness.py --require-siblings --verify-local-hosts`（已接入 `.github/workflows/pr-checklist.yml`），一次性校验：
     - 全部 7 个 `knowledge-*` 领域知识库在历史通道提交与 `HEAD` 之间的单元 `revision` 单调性、`publication-contract.json` 的 `validator.revision` 一致性以及 `routing-manifest.json` / `shard-topology.json` 完整性；
     - 全部 7 个共享运行时组件与 5 款宿主插件的源码标签、锁定哈希（`pyproject.toml`、`uv.lock`、`runtime/active-overrides.txt`、`runtime-requirements.txt`、`product-contract.json`）及 `mcp_catalog.json` 同步性；
     - 本机已安装宿主 CLI（含 ChatGPT Desktop 内置 `codex-cli 0.166.0-alpha.5.1`、`claude`、`kimi`）在各插件 `harness-compatibility.json` 中的版本覆盖率，以及 `channels/0.1.json` 内部与 Release Notes / 文档中心版本表的一致性。

## 2. `mindie-sim v0.9.1`、`mindie-profiler v0.5.5` 与五端插件能力对齐

1. **`mindie-sim v0.9.1` 公理化显存与并行/PD 求解器扩展**：
   - 显式建模 `async_scheduling=True` 下的双缓冲前向工作区、完成请求 KV Block 延迟 1 步释放与前瞻槽位预留，在 `solve_hardware_sla_throughput` 中同步输出 `b_vram_max_sync`、`b_vram_max_async` 及关闭异步调度可释放的并发度 `delta_b_vram_from_disabling_async`；
   - 新增确定性 Case 合成器（`compose_case` / `mindie-sim compose`）及 `efficiency`、`sla`、`sweep`（多维 `DP/TP/EP/PP/PCP` 与 `--mode pd` P/D 分离精确 Pareto 前沿求解）、`skew`（多 DP 上下文偏斜 AllToAllV 同步屏障、MoE 专家失衡 EPLB 与 Chunked-Prefill 最大安全块 $C_{\max}^*$ 物理力学）五大 CLI 子命令；
   - 扩充 Wave 5 模型目录（`deepseek-v2-lite`、`deepseek-v3.2-prune-3l`、`qwen3-30b-a3b`、`qwen3.5-27b`）与 HuggingFace `quantization_config` 角色级量化排除解析（`resolve_role_exclusions`）。
2. **`mindie-profiler v0.5.5` 原生结构切分与 Wave 5 三芯片 `1,653 / 1,653 <= 10%` 样本内校准评估**：
   - 在 Decode/Prefill 结构切分中原生支持 `AddRmsNormQuant`、`SparseFlashAttention`、`SparseFlashMla` 锚点及 DP-partner EP All-to-All Prefill Chunk 对齐；
   - 完成 Wave 5 跨 **A2（`565/565`）+ A3（`580/580`）+ A5（`508/508`）** 共 **202 个 Cohort-Phase、1,653 份** 实测 Golden Profiles（覆盖 `4K..400K` 超长上下文与合成少专家 MoE）的 `100.00% <= 10%` 样本内体制校准评估（平均误差 `2.77%`，中位数 `2.11%`），与独立 856 例 DSH 集群基准（整体 `841/856 = 98.25% <= 15%`，其中 561 例独立 Held-out 盲测 `546/561 = 97.33% <= 15%`）共同构成校准与泛化双层验证。
3. **五端插件同步升级与企业网络 / Windows 安装加固**：
   - 全部 5 款宿主插件（`Codex v0.1.16`、`Claude Code v0.1.12`、`Kimi v0.1.12`、`DSH v0.1.11`、`Google Antigravity v0.1.2`）同步暴露 `mindie-sim 0.9.1` 与 `mindie-profiler 0.5.5` 工具描述，收紧组件输出截断与本地落盘回执边界，并加固企业网络 TLS（`UV_SYSTEM_CERTS` / `UV_NATIVE_TLS`、`GCM_INTERACTIVE=never`）及 Windows LF（`core.longpaths=true`、`core.autocrlf=false`）安装链路。
   - 继承 [`0.1.5` 发布说明](0.1.5.md) 中 Google Antigravity 原生插件架构与 `G0–G5` 全矩阵基准评测结论。
