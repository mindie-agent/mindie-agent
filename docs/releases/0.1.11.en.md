# 0.1.11: preserve tasks across installed runtime upgrades

[中文](0.1.11.md) · [Product combination](../../channels/0.1.json)

Replacing the native AGY/WB plugin directory could combine new handlers with an older component interpreter and fail remote calls before execution. Both adapters release 0.1.8: launch the interpreter and retained payload from the same active profile, prepare compatible components, then activate the new pair.

## Behavior and verification

- Retain payloads by version and content digest. Complete the independent copy before publishing with `os.replace()`, preserving scripts still used by the previous generation.
- Probe required component APIs and reuse the shared runtime builder when an upgrade is needed. Preparation failures retain the previous profile, task entry point, user fields, and job state.
- Linux/Windows CI exercises actual old setup, native directory replacement, preparation failure, dependency upgrade, and MCP calls after activation. Astra max separately verifies an old MCP process remains responsive across replacement and activation, interrupted copies, and content generation reuse.
- Reuse the remaining formal 0.1.10 components and plugins, including automatic password authentication, public key installation and verification, and independent work continuing when optional capabilities fail.

See the [continuity audit](../audits/2026-11-06-task-continuity.md), [release acceptance](0.1.11/task-continuity-release-acceptance.json), and [exact benchmark manifest](0.1.11/benchmark-manifest.json). Running hosts load new catalogs at their natural reload boundary. This release does not claim the current chat has reloaded, or acceptance on private deployment hosts, NPU inference, or model accuracy.
