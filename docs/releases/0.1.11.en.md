# 0.1.11: Preserve Task Continuity Across In-Place Runtime Upgrades

[中文](0.1.11.md) · [Product combination](../../channels/0.1.json)

Previously, overwriting the native Google Antigravity or Tencent WorkBuddy plugin directory on an existing installation could pair newly copied handler scripts with an older component interpreter, causing remote tool calls to fail before dispatch when new helper APIs were absent. This patch releases `0.1.8` for both plugins: the launcher loads both the Python interpreter and its content-addressed retained script payload from the same active profile, stages compatible components first, and atomically switches to the new generation only after validation succeeds.

## Behavior and verification

- **Content-addressed retained script directories**: Handler scripts are copied into a staging directory first and published atomically via `os.replace()` under version- and digest-keyed paths, ensuring in-place overwrites of the native plugin directory never clobber scripts still imported by running processes.
- **API-level compatibility probing & atomic fallback**: Setup probes required shared-component symbols directly and invokes the shared runtime builder whenever an upgrade is needed. If candidate preparation fails, the existing active profile, task entry point, custom user fields, and active background jobs remain intact for retry.
- **Cross-platform upgrade CI & live stdio verification**: Linux and Windows CI test the full lifecycle—initializing from the previous `setup.py`, overwriting the native plugin directory in place, handling staged-build failures, upgrading dependencies, and executing MCP calls after cutover. Independent review (`gpt-6-astra`, `reasoning_effort=max`) additionally verified that an already-running MCP server process stays responsive across directory overwrite and profile cutover, alongside interrupted-copy recovery and digest-directory reuse.
- **Carries forward all `0.1.10` runtime contracts**: All other shared components and host plugins remain pinned to their `0.1.10` releases, preserving one-step `remote_auth(action="setup")` password-to-key onboarding and isolated handling of optional helper failures.

See the [task continuity audit](../audits/2026-11-06-task-continuity.md), [release acceptance receipt](0.1.11/task-continuity-release-acceptance.json), and [exact benchmark manifest](0.1.11/benchmark-manifest.json) for full evidence. Running hosts pick up updated tool catalogs at their natural reload boundary; this release does not claim that an already-open chat session reloads in place, nor does it claim new measurements on private user hosts, NPU inference throughput, or model accuracy.
