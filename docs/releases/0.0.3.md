# MindIE Agent `0.0.3` 版本发布说明

[English](https://github.com/mindie-agent/mindie-agent/blob/v0.0.3/docs/releases/0.0.3.en.md) · [文档中心](https://github.com/mindie-agent/mindie-agent/blob/v0.0.3/docs/README.md)

本文记录 MindIE Agent `0.0.3` 的核心功能更新、十二个配套代码仓库的精确源码清单、各组件价值验证结果与使用说明。

在 `0.0.3` 中，主产品与 OpenAI Codex CLI、Claude Code、Kimi Code、DeepSeek Harness（DSH）四个原生宿主插件统一对齐为 `0.0.3` 版本；底层共享运行时与分析建模组件（`diagnostics`、`knowledge`、`remote-dev`、`coordinator`、`npu-top`、`profiler`、`sim`）及评测工具 `mindie-bench`（`0.4.1`）全部完成正式版发布与基准验证。本次发布重点解决了 `0.0.2` 提出的知识检索上下文开销问题，新增 `profiler` 与 `sim` 两大性能分析与建模组件，补齐 CANN/`plog` 确定性故障分诊与 A5 硬件拓扑支持，并提供了每个组件的可复现价值验证报告。

---

## 一、核心更新

- **知识系统（`knowledge v0.13.0`）：L1–L4 渐进式披露、Token 预算控制与开放探索**：
  - **7 大昇腾公共知识库全量就绪**：统一采用 `mindie-graded-unit/1` 四级结构化知识格式（`L1` 事实与约束标准 · `L2` 标准排障与开发规程 · `L3` 多阶段工程工作流 · `L4` 深度调优模式），覆盖 `vllm-ascend`、`operators`、`infer-core`、`infer-distributed`、`infer-observability`、`infer-ops-compat` 与 `agent-engineering` 七个领域；
  - **渐进式披露与 Token 预算门控**：`query` 仅返回高信噪比候选摘要与适用条件（`applicability`），Agent 按需通过 `explain` 分段读取正文；在 P0–P4 渐进式披露评测中，单次任务知识读取开销严格受控在 `4,814–5,599` tokens（远低于 `8,000` tokens 预算上限），并在跨任务复用（`k=8`）下实现 `+77,280` 至 `+89,120` tokens 的净工程收益；
  - **无偏探索（`mode="explore"`）与子上下文事实包**：支持在开放调优探索中自动过滤既有 `L4` 具体实现方案、仅保留 `L1–L3` 硬件与编译刚性约束以消除先验锚定，并提供原生子上下文事实包组装接口（`assemble_subcontext_fact_pack`）与经验闭环质量门禁。
- **新增面向 Agent 的性能解析与理论建模组件（`profiler v0.5.0` & `sim v0.7.0`）**：
  - **`profiler`（`v0.5.0`）**：支持昇腾 `msprof` 产物就地只读解析（`inventory`、`analyze`、`correlate`、`compare`、`sql`），在毫秒级延迟内完成对齐 Step 拆解、多卡慢卡（如 `Attention` 计算瓶颈）与慢链路（如 `Comm` 通信瓶颈）归因、Host-Device 异步关联以及静态/动态显存拆解（已知桶覆盖率 $\ge 90\%$，未归类残差显式暴露且零数据库写污染）；
  - **`sim`（`v0.7.0`）**：支持昇腾 A2（910B）、A3（910C 双 Die）与 A5（950）四层硬件 Roofline 边界求解、Cube/Vector/MTE 算子流水线排布、子图融合 UB 容量筛查与整网并行推演；内置经 A3 实机校准的 Qwen2.5-7B-Instruct 整网物理预测模型。
- **确定性故障分诊、A5 拓扑兼容与多 Agent 协调增强**：
  - **`diagnostics`（`v0.5.1`）**：新增 CANN 错误码与 `plog` 确定性根因分诊（`analyze_fault_log`），在多卡级联故障中自动识别首发根因 Rank（如 `EZ9999` AICore 访存/Tiling 异常）并区分衍生 `EI9999` HCCL 超时等待 Rank，同时在分诊前强制完成双层隐私脱敏；
  - **`coordinator`（`v0.6.2`）**：新增昇腾 A5（950）`npu-smi` 拓扑探测兼容与多机 HCCL/RoCE 预检能力，提供并发场景下的选卡与端口租约防冲突仲裁；
  - **`npu-top`（`v0.2.1`）**：新增 DCMI 降频/故障原因解码与持久化分数时间窗利用率聚合；
  - **`remote-dev`（`v0.10.4`）**：强化跨机容器补丁解析、工具协议序列化与后台长作业管理。
- **四个原生宿主插件统一升级至 `v0.0.3`**：
  - `mindie-agent-codex`、`mindie-agent-cc`、`mindie-agent-kimi` 与 `mindie-agent-dsh` 全部升级至 `v0.0.3`，锁定 `knowledge v0.13.0`、`remote-dev v0.10.4` 与 `diagnostics v0.5.1` 正式发行版精确 Commit SHA，并在四个宿主上统一支持共享与故障上报开关及渐进式检索工作流。

## 三、各组件价值验证与实测证据

各组件的非 editable 锁定源码实测结果汇总于 [`component-value-results.md`](https://github.com/mindie-agent/mindie-agent/blob/v0.0.3/docs/releases/0.0.3/component-value-results.md)（机器可读原始数据见 [`component-value-results.json`](https://github.com/mindie-agent/mindie-agent/blob/v0.0.3/docs/releases/0.0.3/component-value-results.json)），单仓发布基准见各 Release 随附的 `benchmark-results.md`：

### 1. `coordinator`（`v0.6.2`）与 `remote-dev`（`v0.10.4`）

- **`coordinator` 多 Agent 并发防冲突与快速接管**：
  - 在 3 轮双 Agent 并发抢占压测（`coordinator-contention`）中，无协调基线因“先检查空闲再绑定”竞态仅建立 `3` 个有效监听（每轮 `1` 个），并产生 `3` 次端口绑定冲突与 `3` 次重复选卡；
  - 接入 `coordinator` 租约队列后，**有效监听数翻倍至 `6` 个（每轮 `1 → 2`），端口冲突降为 `0`（`3 → 0`），重复选卡降为 `0`（`3 → 0`）**，前序任务释放后等待方平均 **`2.1 ms`** 即完成租约接管与端口绑定。
- **`remote-dev` 远端容器执行底座**：
  - 延续端到端实机任务提速能力（`quarot` 任务 `3/3` 解出、`1.025x` 交付提速），并在 `v0.10.4` 发布基准中通过补丁解析、工具协议与记录序列化全量校验。

### 2. `profiler`（`v0.5.0`）与 `sim`（`v0.7.0`）

- **`profiler` 慢卡/慢链路定位与显存精准拆解（`profiler-rank-link-memory-attribution`）**：
  - 在 3 轮只读就地解析测试中，无工具基线对原始 `msprof` SQLite 产物的直接瓶颈归因率为 `0%`；
  - `mindie-profiler` 在 **`~8.6 ms`** 内完成对齐 Step 分析、在 **`~0.17 ms`** 内完成跨卡对比、在 **`~0.13 ms`** 内完成显存拆解：**100% 准确区分慢链路（主导块 `Comm`）与慢卡（主导块 `Attention`）**，从 `10.0 GB` 峰值显存中精准归因 **`9.9 GB`（99%）已知显存桶**，将未归类残差收敛在 **`50 MB`（0.5%，满足 `< 10%` 门禁）**，且全程保持原库只读（`db_mutation = False`）。
- **`sim` 算子流水线、子图融合筛查与 A3 整网预测（`sim-a3-graph-and-boundary-screening`）**：
  - 在昇腾 A3（910C）Qwen2.5-7B-Instruct 整网 `c=1` 推演中，预测 TPOT 为 **`15.06 ms`**，对比 A3 实测 `15.71 ms` 的相对误差仅为 **`-4.14%`**（远优于 `±15%` 门禁）；
  - 在算子与子图筛查中，同时输出 `gemm_finite_pipeline` 与 `vector_instruction` 流水排布方案，准确识别子图融合可消除的 **`2.0 MiB` GM 往返流量**与 **`5.0 μs` 关键路径收益**，并 100% 拦截超出 UB 容量上限的非法融合候选（`subgraph_overflow_rejected = True`）。

### 3. `diagnostics`（`v0.5.1`）与 `npu-top`（`v0.2.1`）

- **`diagnostics` 故障去重、隐私脱敏与 CANN/`plog` 确定性根因分诊（`diagnostics-fault-delivery`）**：
  - 3 轮故障上报测试中，每轮 `3` 次重复异常均去重收敛为 **`1` 条上报**，私有路径脱敏、白名单诊断字段保留及撤回授权后立即阻断外发全部 `3/3` 通过；
  - 新增的 CANN/`plog` 确定性分诊在多卡级联报错日志中 **100% 准确锁定首发根因 `Rank 3`（故障域 `aicore_memory_or_tiling`）并区分级联等待超时的 `Rank 7`**，同时将主机 IP、SSH 凭据与本地路径完整脱敏（`fault_log_redacted = True`）。
- **`npu-top` 物理卡、双 Die `Phy-ID` 与实机容器归属映射（`npu-top-physical-owner-query`）**：
  - 在 3 轮 A2/A3 硬件快照回放与常备 A2 实机（`8` 张 910B NPU）实时探测中，**`24/24` 物理设备识别、`16/16` 进程卡号归属映射与 `3/3` 实机 Docker 容器归属校验全部通过**。

### 4. `knowledge`（`v0.13.0`）渐进式披露与闭环飞轮验证

- **检索精度与渐进式上下文预算**：在分级验证中，`technical-tokenization` 检索精度达 **`1.0`**，`graded-feed-lifecycle` 端到端生命周期耗时仅 **`~13.8 ms`**；P0–P4 验收套件（21 项子测试）全部通过，单任务知识读取 Token 开销控制在 `4,814–5,599` tokens（`< 8,000` 上限），解决了 `0.0.2` 长上下文读取开销偏高的问题。

## 四、使用与升级说明

- **插件无感升级与手动升级**：已安装 `0.0.2` 的 Claude Code、OpenAI Codex CLI 与 Kimi Code 环境将在后台空闲窗口自动检测并原子切换至兼容的 `0.0.3` 正式版；也可随时参照[首页安装说明](../../README.md#-一句话无感安装)指定 `v0.0.3` 立即更新。
- **统一贡献与故障上报开关**：社区知识贡献与故障自动上报默认关闭（Opt-in），升级至 `0.0.3` 会完整保留本地已有的 `mindie-consent.json` 授权配置。
