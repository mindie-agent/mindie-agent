# 0.1.12：Windows 后台知识与诊断服务入口修复

[English](0.1.12.en.md) · [产品组合](../../channels/0.1.json)

本版登记 knowledge 0.13.14 与 diagnostics 0.5.8 的 Windows 计划任务入口修复。任务曾仅凭 `pythonw.exe` 文件存在就启动；当该文件实际为控制台型启动器时，已有子进程 `CREATE_NO_WINDOW` 保护无法覆盖它。现在新注册及恢复旧注册任务的实际启动路径都验证真实 PE GUI 子系统，异常在启动前明确报错，修复环境后可以正常重试。

## 行为与验证

- knowledge 保留原虚拟环境身份、参数、正常停止与未知启动不重放的协议，并为实验账本 Git 调用补上 Windows 无窗口标志。
- diagnostics 在安装和已有服务启动前检查 GUI 入口；明确拒绝控制台型、损坏、不可读或缺失的解释器。
- Windows 本地 knowledge 相关范围 204 passed、3 skipped；diagnostics 完整本地套件 329 passed、15 skipped。真实交互式 Windows 计划任务验收 1 passed：服务就绪、虚拟环境及参数保持、没有可见窗口或后代 `conhost.exe`，正常停止、释放锁并删除临时任务。
- 实测环境为 Windows x86_64、uv 0.13.3、CPython 3.13.16；未重装 #115 原始组合，不推断异常二进制的生成来源。Hosted CI 无交互式登录令牌，桌面验收独立运行。
- Kimi 同类定时入口的代码加固另见 [PR #68](https://github.com/mindie-agent/mindie-agent-kimi/pull/68)。本组合继续引用正式 Kimi 0.1.17，不将该未发布源码修复计入正式插件资产。
- 其余正式组件与插件沿用各自标签源码及原始 benchmark，不将历史报告重标为本轮新测量。组件正式 Release、发行包代码、校验和、精确源码 benchmark 与 R1–R6 发布门禁分别核验。
