# 0.1.12：Windows 后台知识与诊断服务入口修复

[English](0.1.12.en.md) · [产品组合](../../channels/0.1.json)

本补丁收录了 `mindie-knowledge v0.13.14` 与 `mindie-diagnostics v0.5.8` 针对 Windows 计划任务（Task Scheduler）启动入口的加固修复。此前后台任务仅凭 `pythonw.exe` 文件存在即直接将其注册为启动器；当部分 Python 发行版中的同名可执行文件实际编译为控制台子系统启动器时，Windows 会在外层子进程 `CREATE_NO_WINDOW` 标志生效前弹出黑色控制台窗口。升级后，新任务注册与既有任务恢复启动前均会解析并校验真实的 PE GUI 子系统（`IMAGE_SUBSYSTEM_WINDOWS_GUI`）：不合规的解释器将在拉起前直接拦截报错，待环境修复后即可正常重试。

## 行为与验证

- **`knowledge` 无窗口后台进程加固**：完整保留原有虚拟环境身份、启动参数、优雅停止协议及“启动状态不确定（`unknown`）时不盲目重放”的安全约束，并为实验账本（`ExperimentLedger`）内部的 Git 子进程调用补齐 Windows 无窗口标志（`CREATE_NO_WINDOW`）。
- **`diagnostics` 启动前 PE GUI 子系统门禁**：在计划任务注册及既有注册项显式拉起前校验解释器 PE 头，明确拒绝控制台子系统、格式损坏、不可读或缺失的二进制入口。
- **Windows 本地测试与交互式桌面实测**：Windows 本地 `knowledge` 受影响范围回归 `204 passed, 3 skipped`；`diagnostics` 全量测试套件 `329 passed, 15 skipped`。真实交互式 Windows 计划任务桌面验收 `1 passed`：确认后台服务就绪、虚拟环境与启动参数保持不变、全程零可见窗口且无后代 `conhost.exe` 驻留，随后正常停止服务、释放锁文件并清理临时计划任务。
- **实测环境与边界说明**：桌面验收运行于 Windows `x86_64`、`uv 0.13.3`、`CPython 3.13.16`（由于托管式 GitHub Actions Runner 缺少交互式桌面登录令牌，该项交互式窗口验收在本地桌面环境独立执行；本轮未重装 Issue `#115` 报告时的历史环境，不对异常启动器二进制的原始生成渠道作主观推断）。
- **关联插件仓库进展**：`mindie-agent-kimi` 同类后台更新定时入口的源码加固见 [PR #68](https://github.com/mindie-agent/mindie-agent-kimi/pull/68)；当前产品通道继续锁定已正式发布的 `Kimi v0.1.17`，不将该尚未发版的源码改动计入正式插件制品。
- **通道资产与门禁核验**：其余共享组件与宿主插件沿用各自正式标签源码及原始基准报告（不将历史基准重标为本轮新实测）；组件正式 GitHub Release、发行包字节、SHA256 校验和、精确源码基准与 `R1–R6` 发布就绪门禁均已逐项核验通过。
