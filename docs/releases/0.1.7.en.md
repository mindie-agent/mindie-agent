# 0.1.7: Native Tencent WorkBuddy Plugin, Standalone `mindie-debugger` Component, `mindie-sim 0.9.3`, 9-Corpus Expansion & 8-Component `G0–G5` Benchmark Verification

[中文](https://github.com/mindie-agent/mindie-agent/blob/v0.1.7/docs/releases/0.1.7.md) · [Product combination](https://github.com/mindie-agent/mindie-agent/blob/v0.1.7/channels/0.1.json) · [V2 Benchmark Report](0.1.7/g0-g5-vllm-ascend-v2-report.en.md) · [144-Trial Summary](0.1.7/g0-g5-vllm-ascend-v2-summary.json) · [34-Task Audit Manifest](0.1.7/g0-g5-vllm-ascend-v2-audit-manifest.json)

This patch release introduces the sixth official native host plugin **`Tencent WorkBuddy v0.1.2`** ([`mindie-agent-wb`](https://github.com/mindie-agent/mindie-agent-wb), supporting both the Tencent WorkBuddy desktop Connector UI and the underlying CodeBuddy Agent CLI), launches the eighth shared runtime component **`mindie-debugger v0.1.0`** ([`mindie-agent/debugger`](https://github.com/mindie-agent/debugger), cleanly separating target Ascend NPU fault triage, 3-primitive precision/memory-stomp localization, and `ACLGraph` zero-sync in-graph replay dumping from Agent internal DFX in `diagnostics`), publishes **`mindie-sim v0.9.3`** (configurable network utilization tiers, DeepEP, AFD, hierarchical expert/KV offload, public SKUs, and custom SKU templates) and **`mindie-profiler v0.5.6`** (`export_sim_calibration` reverse bridge and `xLLM`/`MindIE-SD` support), expands the public domain knowledge ecosystem to **9 Ascend corpora** (`493` graded units total), updates all 6 native host plugins with forward-compatible host ranges and locked component releases, and completes the **V2 100% real `vllm-ascend` 8-component & `G0–G5` benchmark evaluation (34 tasks, 144 trials, zero synthetic toy stubs, zero tool-name spoilers)** across **Codex (`gpt-6.1-sol`, `xhigh`)** and **DSH (`deepseek-flash`, `max`)**.

## 1. Sixth Official Native Host Plugin: `mindie-agent-wb v0.1.2` (Tencent WorkBuddy)

1. **Dual Connector UI & Native Agent Plugin Compatibility**:
   - Ships both the WorkBuddy desktop Connector specification (`plugins/mindie-agent/plugin.json` + `mcp.json` with bilingual `extensions["ai.workbuddy"]` metadata and `660s`/`210s` timeout budgets) and the underlying `@genie/agent-cli` (`codebuddy`) native plugin bundle (`.codebuddy-plugin/plugin.json` + `.mcp.json` + `hooks/hooks.json`).
2. **Full 53-Tool MCP Surface & 13 Native WorkBuddy Remote Tool Mirrors**:
   - Paired with `remote-dev v0.11.4` (`REMOTE_DEV_HARNESS_PROFILE=wb`), exposes all 20 standard `remote_*` tools plus 13 native WorkBuddy remote tool mirrors (`remote_Read`, `remote_Write`, `remote_Edit`, `remote_MultiEdit`, `remote_Bash`, `remote_Glob`, `remote_Grep`, `remote_TaskOutput`, `remote_BashOutput`, `remote_NotebookEdit`, `remote_TaskStop`, `remote_KillShell`, `remote_ViewImage`), alongside `mindie-tools` (14 tools including `debugger`) and `mindie-knowledge` (6 tools).
3. **Lifecycle Hooks & Auto-Update Integration**:
   - Implements per-session `/mindie-agent` lease gating across `SessionStart`, `UserPromptSubmit`, `PreToolUse`, and `Stop`, WorkBuddy Session Store JSONL two-layer redaction, and six-host forward-compatibility verification in `check_auto_update_readiness.py`.

## 2. Standalone Target NPU Debugging Component: `mindie-debugger v0.1.0` & `diagnostics v0.5.5`

1. **Clean Separation of Concerns**:
   - **`mindie-diagnostics v0.5.5`** remains strictly scoped to MindIE Agent's own internal DFX (bounded 4×1 MiB JSONL logs, offline support bundles, and allowlisted GitHub Issue reporting with bounded 2-attempt outbound reconciliation);
   - **`mindie-debugger v0.1.0`** ([`mindie-agent/debugger`](https://github.com/mindie-agent/debugger)) is dedicated to target Ascend NPU workloads (`vllm-ascend`, `xLLM`, `MindIE-SD`, and custom operators), providing:
     - **Deterministic NPU Fault Triage (`npu_fault_triage` / `decode-code`)**: automatic in-container CANN `plog` discovery, error-code decoding (507015/507018/507035/EZ9999/HCCL), live PID environment auditing, and forensic guidance;
     - **3-Primitive Precision & Memory-Stomp Localization (`precision`)**: `npu-watch` (`StorageGraph`, `verify_kv_bounds`, `MemoryWatchpoint`, `WatchRingBuffer`), `call-repro` (FP32 reference checks and jitter vs. quantization loss classification), and `lockstep-diff` (first divergent layer localization and MoE checkpoint slimming);
     - **`ACLGraph` Static-Graph Debugging (`aclgraph`)**: `ACLGraphDumper` (zero-sync in-graph D2D snapshot dumping and per-replay-step eager comparison), `ACLGraphCaptureGuard` (pinpointing `.item()`/`.cpu()` capture violations), and `ACLGraphAddressTracker` (detecting static buffer `data_ptr()` drift and unpadded `slot_mapping` tail corruption).
2. **Managed Component Auto-Update & Benchmark Closure**:
   - `mindie-knowledge v0.13.10` registers `mindie-debugger` in `runtime_inventory.COMPONENTS` and `component_bindings.COMPONENT_MODULES` for independent component updates; `mindie-bench v0.4.6` routes NPU fault triage and precision localization benchmarks through `mindie_debugger`.

## 3. `mindie-sim v0.9.3` & `mindie-profiler v0.5.6` Collaborative Modeling

1. **`mindie-sim v0.9.3` (Configurable Network Tiers, DeepEP, AFD, Hierarchical Offload & SKU Templates)**:
   - Adds configurable network utilization and tier modeling, DeepEP and A5 MC2 communication modeling, AFD (Attention-FFN Disaggregation) Pareto solving, hierarchical expert-weight and KV cache offload (HBM / Host DDR / NVMe SSD, including HiSparse and `memfabric_hybrid`), public hardware SKU presets, and custom SKU template validation.
2. **`mindie-profiler v0.5.6` (Reverse Calibration Bridge to `sim`)**:
   - Adds `export_sim_calibration` to export measured Ascend `msprof` profiling traces directly into `mindie-sim` calibration bundles, alongside first-class `xLLM` and `MindIE-SD` framework support.

## 4. Nine Ascend Domain Corpora, 6-Host Forward Compatibility & Paired Plugin Updates

1. **Nine Public Domain Corpora (`493` Graded Units)**:
   - `mindie-knowledge v0.13.10` and `mindie-coordinator v0.7.3` add first-class framework routing and container provisioning for **`xLLM`** ([`knowledge-xllm`](https://github.com/mindie-agent/knowledge-xllm), 24 units) and **`MindIE-SD`** ([`knowledge-mindie-sd`](https://github.com/mindie-agent/knowledge-mindie-sd), 24 units), while [`knowledge-vllm-ascend`](https://github.com/mindie-agent/knowledge-vllm-ascend) advances to 93 graded units (with `runtime_guard` and KV accuracy compound splits and CJK retrieval aliases).
2. **Forward-Compatible Host Ranges & 6-Plugin Lockstep Release**:
   - Publishes `Codex v0.1.17`, `Claude Code v0.1.13`, `Kimi Code v0.1.13`, `DSH v0.1.12`, `Google Antigravity v0.1.3`, and `Tencent WorkBuddy v0.1.2` with forward-compatible host version intervals and locked SHAs across all 8 shared runtime components.

## 5. 8-Component & `G0–G5` Full-Matrix Benchmark Verification (V2: 100% Real `vllm-ascend` Scenarios · 34 Tasks · 144 Trials)

To quantitatively validate every one of the **8 shared runtime components** and all **6 mechanism tiers (`G0–G5`)** on real production Ascend workloads, we constructed and executed a **34-task, 144-trial V2 benchmark suite built 100% on real `vllm-ascend` production modules (`vllm_ascend/...`, completely retiring legacy `vllm_ascend_diag` synthetic stubs)** across **Codex (`gpt-6.1-sol`, `xhigh`)** and **DSH (`deepseek-flash`, `max`)**, backed by live Ascend A5 8-card nodes (`177.31.22.1`/`25.1`/`27.1`/`28.1`) and standing A3 (`192.168.13.156`). ### 5.1 Three-Gate Anti-Distortion Audit (100% Passed)

1. **Gate 1 (Task & Prompt Purity, `34 / 34` PASS)**: 100% of tasks modify real `vllm_ascend/...` production modules; 100% of `instruction.md` prompts use natural colloquial 1-sentence developer bug reports + raw tracebacks/log paths with **zero tool-name spoilers** (`0` regex hits for `mindie-*` / `npu-top` / `remote-dev` / `mcp__`); 100% pass `verify-soundness` (`before_reward = 0.0 -> after_reward = 1.0`).
2. **Gate 2 (Execution Integrity, `144 / 144` PASS)**: Every `G0` baseline trial has `0` knowledge queries, `0` component calls, and `0` remote calls; all `G2`/`G3`/`G4` tool and knowledge invocations are spontaneously triggered by the Agent; all resolved trials pass multi-shape / Leave-One-Out behavioral verifiers.
3. **Gate 3 (Completeness & Token Accounting, `144 / 144` PASS)**: All 144 trials preserve `trial_receipt.json`, `trajectory.json`, `native_events.jsonl`, `final_patch.diff`, and `verifier.stdout`, with `provider_total == input_uncached + input_cached + output`.
