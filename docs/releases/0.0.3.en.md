# MindIE Agent `0.0.3` Release Notes

[中文](https://github.com/mindie-agent/mindie-agent/blob/v0.0.3/docs/releases/0.0.3.md) · [Documentation Center](https://github.com/mindie-agent/mindie-agent/blob/v0.0.3/docs/README.en.md)

This document records the key feature updates, exact 12-repository source manifest, component value verification results, and upgrade notes for MindIE Agent `0.0.3`.

In `0.0.3`, the main product and all four native host plugins—OpenAI Codex CLI, Claude Code, Kimi Code, and DeepSeek Harness (DSH)—align on version `0.0.3`, while all shared runtime and analysis/modeling packages (`diagnostics`, `knowledge`, `remote-dev`, `coordinator`, `npu-top`, `profiler`, `sim`) and `mindie-bench` (`0.4.1`) ship formal verified releases. This release resolves the context-reading overhead noted in `0.0.2` via L1–L4 progressive disclosure and token budget enforcement, introduces the `profiler` and `sim` components, adds deterministic CANN/`plog` root-cause triage and Ascend A5 topology support, and delivers reproducible value verification across every component.

---

## 1. Key Changes

- **Knowledge System (`knowledge v0.13.0`): L1–L4 Progressive Disclosure, Token Budgets & De-Biased Exploration**:
  - **7 Public Ascend Knowledge Corpora**: Standardized on the `mindie-graded-unit/1` graded schema (`L1` Canonical Facts & Constraints · `L2` Standard Operating Procedures · `L3` Multi-Stage Workflows · `L4` Optimization Patterns) across `vllm-ascend`, `operators`, `infer-core`, `infer-distributed`, `infer-observability`, `infer-ops-compat`, and `agent-engineering`;
  - **Progressive Disclosure & Token Budget Gating**: `query` returns compact candidate cards with explicit `applicability` conditions while `explain` loads full sections on demand; across the P0–P4 acceptance suite, per-task knowledge reading stays strictly bounded at `4,814–5,599` tokens (`< 8,000` budget ceiling) while yielding a net multi-task benefit of `+77,280` to `+89,120` tokens at `k=8`;
  - **De-Biased Exploration (`mode="explore"`) & Subcontext Fact Packs**: Automatically filters prior `L4` optimization patterns during open-ended kernel/model exploration (retaining only `L1–L3` hardware and compiler invariants to prevent anchoring) and provides native subcontext fact-pack assembly (`assemble_subcontext_fact_pack`) plus closed-loop distillation verification.
- **New Agent-Facing Profiling & Performance Modeling Components (`profiler v0.5.0` & `sim v0.7.0`)**:
  - **`profiler` (`v0.5.0`)**: In-place read-only Ascend `msprof` analysis (`inventory`, `analyze`, `correlate`, `compare`, `sql`) with millisecond turnaround, aligned-step stage attribution, slow-rank (`Attention`) vs. slow-link (`Comm`) bottleneck localization, Host-to-Device correlation, and static/dynamic memory decomposition ($\ge 90\%$ known-bucket coverage with explicit residual reporting and zero SQLite mutation);
  - **`sim` (`v0.7.0`)**: Four-layer hardware roofline and boundary solver across Ascend A2 (910B), A3 (910C dual-Die), and A5 (950), supporting Cube/Vector/MTE operator pipeline scheduling, subgraph fusion UB-capacity screening, and whole-network parallelism modeling calibrated against live A3 hardware.
- **Deterministic Fault Triage, A5 Topology Support & Multi-Agent Coordination**:
  - **`diagnostics` (`v0.5.1`)**: Adds deterministic CANN/`plog` fault triage (`analyze_fault_log`) that separates root-cause ranks (e.g., `EZ9999` AICore memory/tiling faults) from cascading `EI9999` HCCL timeout ranks while enforcing two-layer privacy redaction prior to triage;
  - **`coordinator` (`v0.6.2`)**: Adds Ascend A5 (950) `npu-smi` topology parsing and multi-node HCCL/RoCE preflight checks alongside concurrent NPU/port lease arbitration;
  - **`npu-top` (`v0.2.1`)**: Adds DCMI throttling/fault cause decoding and persisted fractional-window utilization aggregation;
  - **`remote-dev` (`v0.10.4`)**: Hardens cross-host container patch parsing, tool protocol serialization, and background job lifecycle management.
- **Unified `v0.0.3` Host Plugins**:
  - `mindie-agent-codex`, `mindie-agent-cc`, `mindie-agent-kimi`, and `mindie-agent-dsh` all align on `v0.0.3`, pinning the exact formal release commits of `knowledge v0.13.0`, `remote-dev v0.10.4`, and `diagnostics v0.5.1` with unified consent management across all four hosts.

## 3. Component Value Verification & Measured Evidence

Measured component value benchmarks executed against the exact non-editable `0.0.3` formal commits are summarized in [`component-value-results.md`](https://github.com/mindie-agent/mindie-agent/blob/v0.0.3/docs/releases/0.0.3/component-value-results.md) (raw JSON at [`component-value-results.json`](https://github.com/mindie-agent/mindie-agent/blob/v0.0.3/docs/releases/0.0.3/component-value-results.json)), alongside per-repository `benchmark-results.md` assets on each GitHub Release:

### 1. `coordinator` (`v0.6.2`) & `remote-dev` (`v0.10.4`)

- **`coordinator` Multi-Agent Anti-Collision & Fast Lease Handoff**:
  - Across 3 two-agent contention runs (`coordinator-contention`), the uncoordinated check-then-bind baseline established only `3` active listeners (`1` per run) while suffering `3` port bind conflicts and `3` duplicate device selections;
  - With `coordinator`'s lease queue, **active listeners doubled to `6` (`1 → 2` per run), port conflicts dropped to `0` (`3 → 0`), and duplicate device selections dropped to `0` (`3 → 0`)**, with the waiting agent acquiring the released lease in **`~2.1 ms`**.
- **`remote-dev` Remote Container Execution Substrate**:
  - Retains verified live end-to-end speedup (`3/3` solved and `1.025x` faster delivery on `quarot`) while passing all patch-parser, tool-protocol, and record-serialization release benchmarks in `v0.10.4`.

### 2. `profiler` (`v0.5.0`) & `sim` (`v0.7.0`)

- **`profiler` Slow-Rank / Slow-Link Attribution & Memory Decomposition (`profiler-rank-link-memory-attribution`)**:
  - Across 3 in-place read-only runs on `msprof` SQLite artifacts, `mindie-profiler` completes aligned-step stage analysis in **`~8.6 ms`**, cross-rank comparison in **`~0.17 ms`**, and memory breakdown in **`~0.13 ms`**;
  - **100% accurately distinguishes slow-link (`Comm`) from slow-rank (`Attention`) bottlenecks**, attributes **`9.9 GB` (99%) of a `10.0 GB` peak allocation** to known memory buckets with **`50 MB` (0.5%, `< 10%` target) explicit residual**, and mutates zero bytes of the source SQLite files (`db_mutation = False`).
- **`sim` Operator Pipeline, Subgraph Screening & Calibrated A3 Modeling (`sim-a3-graph-and-boundary-screening`)**:
  - On Ascend A3 (910C) Qwen2.5-7B-Instruct `c=1` whole-network inference, predicts a TPOT of **`15.06 ms`** against the measured **`15.71 ms`** (**`-4.14%` error**, well within the `±15%` gate);
  - Produces both `gemm_finite_pipeline` and `vector_instruction` operator schedules, identifies **`2.0 MiB` of removable GM traffic** and **`5.0 μs` critical-path savings** from legal subgraph fusion, and deterministically rejects UB-overflowing fusion candidates (`subgraph_overflow_rejected = True`).

### 3. `diagnostics` (`v0.5.1`) & `npu-top` (`v0.2.1`)

- **`diagnostics` Fault Deduplication, Redaction & Deterministic CANN/`plog` Triage (`diagnostics-fault-delivery`)**:
  - Across 3 fault-reporting runs, `3` repeated failures per run are deduplicated into **`1` delivered report** with `3/3` passes on path redaction, diagnostic field retention, and immediate stop upon consent withdrawal;
  - Deterministic CANN/`plog` fault triage (`analyze_fault_log`) **100% identifies root-cause `Rank 3` (`aicore_memory_or_tiling`) while separating cascading `HCCL` timeout `Rank 7`**, with full redaction of host IPs, SSH credentials, and local paths (`fault_log_redacted = True`).
- **`npu-top` Physical Device, Dual-Die `Phy-ID` & Live Container Attribution (`npu-top-physical-owner-query`)**:
  - Across 3 A2/A3 hardware-capture replays and live standing A2 cluster probes (`8` physical 910B NPUs), all **`24/24` physical devices, `16/16` process-to-card mappings, and `3/3` live Docker container ownership checks passed**.

### 4. `knowledge` (`v0.13.0`) Progressive Disclosure & Closed-Loop Verification

- **Retrieval Precision & Bounded Context Budget**: Achieves **`1.0` precision** on `technical-tokenization` and **`~13.8 ms`** full lifecycle latency on `graded-feed-lifecycle`; all 21 checks in the P0–P4 progressive disclosure and Hermes/RSI closed-loop suites pass, bounding single-task context reading to `4,814–5,599` tokens (`< 8,000` ceiling).

## 4. Upgrade & Usage Notes

- **Silent & Manual Upgrades**: Existing `0.0.2` installations on Claude Code, OpenAI Codex CLI, and Kimi Code automatically check for and atomically switch to `0.0.3` during an idle background window, or can be upgraded immediately using the `v0.0.3` commands in the [README Install Guide](../../README.en.md#-zero-friction-one-sentence-install).
- **Unified Contribution & Fault-Reporting Consent**: Community knowledge sharing and fault reporting remain opt-in (`off` by default); upgrading to `0.0.3` preserves your existing `mindie-consent.json` preferences.
