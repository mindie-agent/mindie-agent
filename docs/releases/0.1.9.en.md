## Behavior changes

- **Establish reusable SSH access**: public `remote_auth(action="setup")` accepts an ephemeral password, installs a public key through the shared implementation, and verifies it in a fresh process. Passwords are excluded from configuration, receipts, and persistent environment variables. Existing working identities are reused.
- **Keep independent work moving**: unavailable knowledge, onboarding, diagnostics, optional components, and local accounting affect their capability. Continue independent authorized native work while retaining task identity, permissions, resource reservations, and active jobs.
- **Keep MCP connections alive after individual failures**: Antigravity and WorkBuddy return request-scoped admission or accounting errors while continuing to serve ping, tool discovery, and independent requests. Antigravity rejects consumed one-shot bindings without inheriting a previous conversation identity.
- **Preserve primary outcomes**: successful remote authentication remains successful when local profile recording fails. An unsaved profile creates neither a fake `auth_ref` nor a ready Coordinator host. Shared outcome classification distinguishes success, failure, and uncertain external writes, which require reconciliation before retrying.

## Validation scope

Two independent `gpt-6-astra / max` reviews closed three confirmed P1 findings. Validation covers isolated regressions, public MCP parameters and dispatch, real stdio request sequences, and SQLite receipts. Real OpenSSH acceptance covers PowerShell, Windows PowerShell 5, and WSL2. Each final plugin commit also passes repository CI and benchmarks built from its exact release tag.

See the [task continuity audit](../audits/2026-11-06-task-continuity.md) and [first-time SSH contract audit](../audits/2026-11-06-ssh-auth-contract.md) for evidence and limits. No private deployment-host, NPU inference, or model accuracy acceptance is claimed.

Existing updaters can discover the formal components and plugins. Candidate preparation, installed binding activation, and host loading of new tool definitions are separate states. Running hosts retain their natural reload or fresh-process boundary without forcing active conversations to end.
