# 0.1.8：统一单状态源 RSI 闭环引擎（`mindie-knowledge 0.13.11`）、分级检索默认预算翻倍、过期服务退役修复与六大宿主 `G4` 真题全量验证

[English](https://github.com/mindie-agent/mindie-agent/blob/v0.1.8/docs/releases/0.1.8.en.md) · [产品组合](https://github.com/mindie-agent/mindie-agent/blob/v0.1.8/channels/0.1.json)

本补丁版本发布 **`mindie-knowledge v0.13.13`**（[`mindie-agent/knowledge`](https://github.com/mindie-agent/knowledge)）及配套的六大官方原生客户端插件 **`Codex v0.1.20`**、**`Claude Code v0.1.16`**、**`Kimi Code v0.1.14`**、**`DSH v0.1.15`**、**`Google Antigravity v0.1.6`** 与 **`Tencent WorkBuddy v0.1.5`**：将递归自我改进（RSI）闭环收敛至单一权威状态源 `ExperimentLedger`（`orient` / `propose` / `verdict` 三原语闭环），将分级知识检索默认 Token 预算提升至 `explore 24000` / `query 8000` / `explain 16000`（上限 `64000`），修复被取代后台服务（`state=replaced`）残留阻塞 `service replace` 的问题（`mindie-agent-codex#85`），将全部六端插件统一对齐至 `mindie-sim v0.9.4`，并在全部六大宿主上完成 `mindie-bench` 真实 `vllm-ascend` `G4` 工程任务端到端实测验收（`6 / 6` 宿主 `reward = 1.0`）。

## 1. 统一单状态源 RSI 闭环引擎（`mindie-knowledge v0.13.13`）

1. **收敛双状态文件，消除重入状态漂移**：
   - 将原分离的 `rsi-loop-state.json` 与 `experiment-ledger.jsonl` 统一收敛至唯一权威存储 `ExperimentLedger`（`graded/experiment_ledger.py`），`RSILoopEngine`（`graded/rsi_loop.py`）作为无独立状态副本的纯协调层提供 `orient` / `propose` / `verdict` 三原语闭环。
   - 完整支持被取代基线（`superseded`）回退对账、历史轮次指定 `record_id` 重试保序与无 `bottleneck_summary` 的反驳记录（`refuted`）恢复。
2. **`knowledge_explore` 原生内嵌 `active_rsi_session`**：
   - 当会话存在活跃 RSI 探索账本时，`knowledge_explore` 自动返回当前轮次、已封禁瓶颈家族（`refuted_families`）与下一步推荐动作，引导 Agent 零额外工具调用直接推进实验验证。

## 2. 分级知识检索默认 Token 预算翻倍与过期服务安全退役

1. **适配真实复杂工程任务的检索预算（`graded/context_manager.py` / `graded/explore.py`）**：
   - `knowledge_explore` 默认 `token_budget` 由 `12000` 提升至 **`24000`**；
   - `knowledge_query` 默认 `token_budget` 由 `4000` 提升至 **`8000`**；
   - `knowledge_explain` 默认 `token_budget` 由 `8000` 提升至 **`16000`**；
   - 单次检索最大预算上限（`MAX_TOKEN_BUDGET`）扩展至 **`64000`**。
2. **修复 `state=replaced` 残留服务阻塞 `service replace`（`mindie-agent-codex#85`）**：
   - 在 `loop/cli.py` 与 `loop/systemd_service.py` 中对已被新世代取代的 `state=replaced` 旧服务及启动记录（`service-launch.json`）补齐进程身份校验与安全退役回收。

## 4. Ascend 950DT (A5) 场景 16 组受控 CPU 契约 RSI 自动晋升与 C6 沉淀 A/B 评测（`track-RSI-E2E-v4`）

面向 **Ascend 950DT (A5)** 场景的 4 个受控 CPU 张量与消融契约任务 Fixture（`vllm-ascend-mla-prolog-rope-kvcache-fusion-rsi-zh`、`dsv4-sparse-mla-qli-fusion-rsi-zh`、`vllm-ascend-dspark-mtp-aclgraph-d2h-rsi-zh`、`triton-spatial-norm-dim-merge-rsi-zh`；`validation_scope="controlled_cpu_tensor_and_ablation_contract"`，非真机 NPU 吞吐/时延实测），在严格单一变量控制（同一任务 `G2` 与 `G4` 共享完全相同的 `task_digest`、`corpus_commit`、初始 `corpus_view_sha256` 与共享 `L1–L3` 工作流指引，无组间差异化提示词干预）下完成双宿主（**Codex `gpt-6.1-sol (xhigh)`** 与 **DSH `deepseek-flash (max)`**）16 组端到端 A/B 实验，并附 **Codex `gpt-6-astra (max)`** 独立产物核验报告：

- **受控 CPU 契约通过率**：对照组 `G2`（`MINDIE_DISABLE_RSI_EXPLORE=1` 物理剥离 `L4`）受控契约通过率 **`0 / 8 (0.0%)`**（账本实际记录每组 `3..8` 个、合计 35 个独立证伪候选哈希但无法晋升；注：如 `codex/G2/mla-prolog` 已满足基础张量误差 `max_abs_error=0.0`，但因缺少 `L4` 消融报告契约而判 `0.0`），实验组 `G4`（自动切 RSI + Stop 阶段 `graded-c6` 沉淀）通过率 **`8 / 8 (100.0%)`**（受控契约得分净差 **`+100.0 pp`**）。
- **无显式 `explore` 调用的自动晋升（共享 `L3` 工作流引导下）**：`8 / 8` 组 `G4` 实验首次进入 `explore` 均由 `requested_mode="reuse"` 在工作区账本累计满 `3` 个不同 `candidate_sha256` 的被证伪候选后自动触发（首次晋升 `auto_switched_from_reuse=True`，且全程 `caller_initiated_explore=False`；注：`G2` 与 `G4` 均接收相同的共享 `L3` 阶段性验证与重查工作流指引，即“无组间差异化辅导”而非“零流程引导”）。
- **Stop 阶段 `graded-c6` 本地沉淀闭环**：`8 / 8` 组 `G4` 实验全部完成 `graded-c6` 提炼、Gitleaks 脱敏与本地裸 Git 仓库（`knowledge-private/local_knowledge.git`）提交（`c6_distill_status="completed:applied"`）。
- **独立第三方核验结论与方法学边界（Codex `gpt-6-astra max`）**：5 项受控产物核验（`G2/G4` 单一变量一致性、`G2` 物理 `L4` 隔离、`8/8` `G4` 首次 `reuse -> explore` 自动晋升、公开测试文件零明文私有消融键泄露、`16/16` 评测器重放与 `8/8` 本地 `C6` Git 提交）全部 **PASS**；同时明确方法学边界：本基准验证的是受控 CPU 契约与共享 `L3` 引导下的机制闭环（且 v4 原始 `dspark` 评测输出仅记录 `full_candidate` 探针，已在 `mindie-bench 0.4.7` 中补齐强制四臂留一法校验），不等同于无引导真机 A5 性能加速证明。
