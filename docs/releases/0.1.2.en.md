# 0.1.2: Enter an SSH password once and reuse it across processes, chats, and plugins

This maintenance patch handles connections where a public key is rejected and password authentication is needed. It also removes repeated password entry when an Agent changes process, chat, or plugin. `remote-dev` owns the shared SSH authentication implementation; `coordinator` and `npu-top` reuse the same profiles and credentials.

The product composition uses `remote-dev 0.11.1`. After `0.11.0` passed the original three-environment acceptance, downstream Git Bash CI exposed Git for Windows 2.56.0's `ucrt64/bin` layout. `0.11.1` corrects SSH discovery and adds real password and key tests under that inherited PATH. The `0.11.0` tag and reports remain intact; no tag was moved and no historical result was rewritten.

The three shared components and four host plugins have verified formal Releases, source tags, package contents, and benchmark reports. The product composition also aligns diagnostics to the previously published `0.5.4`; the other component pins and seven corpus snapshots are preserved.

## Configure once

Enter the remote SSH password through a hidden terminal prompt:

```bash
remote-dev auth setup --host 192.0.2.10 --port 22 --user root --prompt
```

Setup first checks existing OpenSSH identities. When a public key is needed, it installs and independently verifies the selected key while retaining the password for recovery. If the server rejects public keys but accepts the password, later processes use the saved password authentication method. Add `--no-install-key` to explicitly use passwords only. `--password-env VARIABLE` imports the secret once; subsequent processes do not need the original variable. Automation may also import a password through standard input.

Profiles live under the current user's `~/.mindie/ssh`, indexed by the exact `host + port + user`. Secrets are stored in the local plaintext file `credentials.json`; profiles contain references. The directory and files use the platform's user access controls. This module does not call an OS keychain or credential vault, and does not request a system login password, an unlock password, or another master password. Protect this directory like an SSH private-key directory.

Processes, chats, and plugins running as the same operating-system user in the same environment share authentication. Native Windows and WSL use their respective user directories; secrets are not copied between them automatically. All consumers must use the same configuration when overriding `REMOTE_DEV_AUTH_DIR` or `REMOTE_DEV_CREDENTIAL_FILE`. Host aliases and IP addresses are not automatically merged into one connection identity.

## Key repair, read-only monitoring, and failure semantics

- For key profiles with a saved recovery password, development calls check the key before submitting business commands. Only a confirmed authentication rejection permits password verification and reinstallation of the same key. The business command is submitted once.
- A shared installer preserves existing `authorized_keys` entries, including files without a final newline. It does not change `sshd` configuration.
- If password authentication works but key maintenance fails, the connection remains usable with the password and the result exposes the maintenance facts. Failed maintenance, completed installation, and uncertain remote writes remain distinct. An uncertain maintenance result stops the current call while retaining the password; it is not reported as success or used to justify replaying business commands.
- Read-only diagnostics and `npu-top` monitoring can fall back from the key to the saved password within one SSH handshake. They do not repair public keys or rewrite profiles. Host-key conflicts remain errors.
- `auth status` reports non-secret state. `auth forget` removes the local connection profile and saved password without revoking remote keys or deleting the shared private key. Run setup again after changing the remote password.

Native Windows uses the installed `remote-dev-askpass.exe` entry point and sends passwords to SSH as UTF-8 bytes. POSIX uses an isolated helper from the same authentication module. One-time codes, interactive MFA, and expired-password change dialogs are outside the saved-password flow.

They expose `remote_auth` with `password_env` and no plaintext `password` argument. The installed knowledge baselines are `0.13.4` for Codex/Claude Code and `0.13.3` for Kimi/DSH; the acceptance record preserves those differences.
