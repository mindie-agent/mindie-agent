# 0.1.11：已安装运行时升级的任务连续性修复

[English](0.1.11.en.md) · [产品组合](../../channels/0.1.json)

## 行为与验证

- 以版本及内容摘要区分保留脚本，独立复制完成后通过 `os.replace()` 发布。原生目录覆盖不会覆盖仍在使用的旧脚本。
- 兼容性检查覆盖实际组件 API；缺少 API 时复用共享构建器准备新运行时。准备失败保留原配置、任务入口、用户字段和作业状态，后续仍可重试。
- 真实旧 setup 初始化、覆盖原生目录、候选失败、现场构建升级与激活后的 MCP 调用在 Linux/Windows CI 中验证。Astra max 另行验证同一个旧 MCP 进程在覆盖及激活期间继续响应，以及复制中断与摘要目录复用。
- 沿用 0.1.10 正式组合的其余组件与插件，保留用户已给出 SSH 密码时自动认证、安装公钥和验证密钥访问的行为，以及可选能力故障只影响对应步骤的边界。

具体证据见[任务连续性审计](../audits/2026-11-06-task-continuity.md)、[发布验收](0.1.11/task-continuity-release-acceptance.json)与[精确基准清单](0.1.11/benchmark-manifest.json)。已有宿主进程通过自然重载加载新工具目录；本次不声称当前聊天已重载，也不声称用户业务机器、NPU 推理或模型精度已经实测。
