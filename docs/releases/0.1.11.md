# 0.1.11：已安装运行时原位升级的任务连续性修复

[English](0.1.11.en.md) · [产品组合](../../channels/0.1.json)

此前在 Google Antigravity 与 Tencent WorkBuddy 旧有安装环境中，当原生插件目录被直接覆盖更新后，启动器可能将新版转发脚本与旧版组件解释器混搭运行，导致远端工具调用在分发前即因缺少新增 API 而失败。本版本同步发布两端插件 `0.1.8`：启动器统一从同一份激活配置中成对加载解释器与按版本/内容摘要隔离的保留脚本目录，并在探测与构建好兼容组件运行时后再原子切换激活配置。

## 行为与验证

- **按版本与内容摘要隔离保留脚本**：脚本先完整复制至独立临时目录，再通过 `os.replace()` 原子发布至按版本与内容哈希命名的保留目录；即使宿主原生插件目录被原位覆盖，正在运行的旧代进程仍可安全读取对应的原版脚本。
- **按实际组件 API 探测并预构建兼容环境**：安装与升级流程显式探测所需的共享组件符号，缺失时自动调用共享构建器准备新版虚拟环境；若候选环境构建失败，则完整保留上一代激活配置、任务入口、用户自定义字段与在途作业状态，支持后续无缝重试。
- **跨平台原位升级与长连接存活验证**：Linux 与 Windows CI 实跑覆盖“旧版 `setup.py` 初始化 → 原位覆盖原生插件目录 → 候选构建失败回退 → 依赖升级激活 → 激活后 MCP 工具调用”全链路；独立代码审查（`gpt-6-astra`，`reasoning_effort=max`）另行验证了同一旧代 MCP 子进程在目录覆盖与配置切换期间持续响应请求、复制中断恢复及相同内容摘要目录复用。
- **继承 `0.1.10` 全部正式组件与连续性契约**：其余共享组件与宿主插件沿用 `0.1.10` 正式版本组合，完整保留 `remote_auth(action="setup")` 一次性密码装钥验证及可选能力故障局部隔离机制。

详细审计证据见[任务连续性审计](../audits/2026-11-06-task-continuity.md)、[发布验收回执](0.1.11/task-continuity-release-acceptance.json)与[精确基准清单](0.1.11/benchmark-manifest.json)。已在运行中的宿主进程将在各自的自然重载边界加载新版工具目录；本说明不声称当前活跃聊天已即时完成宿主重载，也不额外声称对用户私有业务机器、NPU 推理吞吐或模型精度进行了重新实测。
