## 1. Three-Layer Prevention of Auto-Update Blockers

1. **Authoring Auto-Advance (`build_routing_index`)**:
   - In `mindie-knowledge v0.13.8`, `build_routing_index()` compares each unit's `content_sha256` against the existing `index/routing-manifest.json` and `HEAD`. Whenever a unit's content changes without advancing `revision`, `build_routing_index()` automatically updates `revision: old_revision + 1` in the unit `.md` file before writing the routing manifests (and fails with `revision_not_advanced` when `check=True`).
2. **Publication Monotonicity Gate (`publication_check.py`) & Client Repair Tolerance**:
   - `mindie_knowledge/publication_check.py` enforces `_validate_graded_revision_advance()` during `validate(..., base_revision=...)`, rejecting any `mindie-publication-contract/2` commit that alters `content_sha256` without incrementing `revision`;
   - `GradedRepository.install_feed()` allows monotonic `unit.revision >= old.revision` updates when `content_sha256` is unchanged, so repair commits never block clients that synced an intermediate commit.
3. **Mandatory Pre-Release Auto-Update Readiness Gate (`.github/scripts/check_auto_update_readiness.py`)**:
   - Adds `python3 .github/scripts/check_auto_update_readiness.py --require-siblings --verify-local-hosts` (also wired into `.github/workflows/pr-checklist.yml`), verifying before any release:
     - Semantic `revision` monotonicity across channel history and `HEAD`, `publication-contract.json` `validator.revision` alignment, and `routing-manifest.json` / `shard-topology.json` integrity across all 7 `knowledge-*` corpora;
     - Tag/SHA/lockfile alignment across all 7 shared runtime components and 5 host plugins;
     - Local host CLI version coverage (`codex` including ChatGPT Desktop `0.166.0-alpha.5.1`, `claude`, and `kimi`) against each plugin's `harness-compatibility.json`.
   - Carries forward the native Google Antigravity plugin architecture and full `G0–G5` benchmark verification documented in the [`0.1.5` release notes](0.1.5.en.md).
