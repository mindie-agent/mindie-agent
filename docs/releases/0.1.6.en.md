## 1. Three-Layer Prevention of Auto-Update Blockers

1. **Authoring Auto-Advance (`build_routing_index`)**:
   - In `mindie-knowledge v0.13.8`, `build_routing_index()` compares each unit's `content_sha256` against the existing `index/routing-manifest.json` and `HEAD`. Whenever a unit's content changes without advancing `revision`, `build_routing_index()` automatically updates `revision: old_revision + 1` in the unit `.md` file before writing the routing manifests (and fails with `revision_not_advanced` when `check=True`).
2. **Publication Monotonicity Gate (`publication_check.py`) & Client Repair Tolerance**:
   - `mindie_knowledge/publication_check.py` enforces `_validate_graded_revision_advance()` during `validate(..., base_revision=...)`, rejecting any `mindie-publication-contract/2` commit that alters `content_sha256` without incrementing `revision`;
   - `GradedRepository.install_feed()` allows monotonic `unit.revision >= old.revision` updates when `content_sha256` is unchanged, so repair commits never block clients that synced an intermediate commit.
3. **Mandatory Pre-Release Auto-Update Readiness Gate (`.github/scripts/check_auto_update_readiness.py`)**:
   - Adds `python3 .github/scripts/check_auto_update_readiness.py --require-siblings --verify-local-hosts` (also wired into `.github/workflows/pr-checklist.yml`), verifying before any release:
     - Semantic `revision` monotonicity across channel history and `HEAD`, `publication-contract.json` `validator.revision` alignment, and `routing-manifest.json` / `shard-topology.json` integrity across all 7 `knowledge-*` corpora;
     - Tag/SHA/lockfile alignment across all 7 shared runtime components and 5 host plugins;
     - Local host CLI version coverage (`codex` including ChatGPT Desktop `0.166.0-alpha.5.1`, `claude`, and `kimi`) against each plugin's `harness-compatibility.json`, plus full version alignment between `channels/0.1.json`, release notes, and documentation center tables.

## 2. `mindie-sim v0.9.1`, `mindie-profiler v0.5.5` & 5-Host Plugin Alignment

1. **`mindie-sim v0.9.1` Axiomatic Memory & Parallel/PD Pareto Solvers**:
   - Explicitly models `async_scheduling=True` HBM overheads (ping-pong forward workspaces, 1-step delayed KV block release, and in-flight lookahead slot reservation), reporting both `b_vram_max_sync` and `b_vram_max_async` plus `delta_b_vram_from_disabling_async` in `solve_hardware_sla_throughput`;
   - Adds deterministic Case composition (`compose_case` / `mindie-sim compose`) and CLI subcommands `efficiency`, `sla`, `sweep` (multi-dimensional `DP/TP/EP/PP/PCP` and `--mode pd` P/D disaggregation Pareto frontier solver), and `skew` (multi-DP context skew AllToAllV barrier wait, MoE routing imbalance with EPLB, and Chunked-Prefill max safe chunk size $C_{\max}^*$ mechanics);
   - Expands the Wave 5 model catalog (`deepseek-v2-lite`, `deepseek-v3.2-prune-3l`, `qwen3-30b-a3b`, `qwen3.5-27b`) and HuggingFace role-level quantization exclusion parsing (`resolve_role_exclusions`).
2. **`mindie-profiler v0.5.5` Native Segmentation & Wave 5 `1,653 / 1,653 <= 10%` In-Sample Calibration**:
   - Extends native Decode and Prefill structure segmentation with `AddRmsNormQuant`, `SparseFlashAttention`, `SparseFlashMla`, and DP-partner EP all-to-all Prefill chunk alignment;
   - Completes Wave 5 multi-chip in-sample regime calibration across **A2 (`565/565`) + A3 (`580/580`) + A5 (`508/508`)** covering **202 cohort-phase pairs and 1,653 Golden Profiles** (`4K..400K` ultra-long context and synthetic reduced-expert MoE topologies) with **`100.00% <= 10%` error** (mean `2.77%`, median `2.11%`), complementing the separate 856-case DSH fleet generalization benchmark (`841/856 = 98.25% <= 15%` overall, `546/561 = 97.33% <= 15%` on independent held-out cases).
3. **Five-Host Plugin Upgrades & Enterprise-Network / Windows Hardening**:
   - All 5 official host plugins (`Codex v0.1.16`, `Claude Code v0.1.12`, `Kimi v0.1.12`, `DSH v0.1.11`, and `Google Antigravity v0.1.2`) synchronize `mindie-sim 0.9.1` and `mindie-profiler 0.5.5` MCP tool catalogs, decouple component output truncation from local spool receipts, and harden enterprise TLS (`UV_SYSTEM_CERTS` / `UV_NATIVE_TLS`, `GCM_INTERACTIVE=never`) and Windows LF (`core.longpaths=true`, `core.autocrlf=false`) installation paths.
   - Carries forward the native Google Antigravity plugin architecture and full `G0–G5` benchmark verification documented in the [`0.1.5` release notes](0.1.5.en.md).
