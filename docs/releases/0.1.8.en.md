# 0.1.8: Unified Single-State RSI Loop Engine (`mindie-knowledge 0.13.11`), Doubled Graded Retrieval Token Budgets, Superseded Service Retirement & 6-Host `G4` Real-Task Verification

[中文](https://github.com/mindie-agent/mindie-agent/blob/v0.1.8/docs/releases/0.1.8.md) · [Product combination](https://github.com/mindie-agent/mindie-agent/blob/v0.1.8/channels/0.1.json)

This patch release publishes **`mindie-knowledge v0.13.13`** ([`mindie-agent/knowledge`](https://github.com/mindie-agent/knowledge)) alongside updated releases for all six official native host plugins — **`Codex v0.1.20`**, **`Claude Code v0.1.16`**, **`Kimi Code v0.1.14`**, **`DSH v0.1.15`**, **`Google Antigravity v0.1.6`**, and **`Tencent WorkBuddy v0.1.5`**: consolidating the Recursive Self-Improvement (RSI) state machine onto a single authoritative `ExperimentLedger` (`orient` / `propose` / `verdict`), raising default graded knowledge retrieval token budgets to `explore 24000` / `query 8000` / `explain 16000` (ceiling `64000`), fixing stale `state=replaced` service owner retirement during `service replace` (`mindie-agent-codex#85`), aligning all six plugins to `mindie-sim v0.9.4`, and verifying end-to-end real-task `G4` execution across all six hosts (`6 / 6` hosts `reward = 1.0`).

## 1. Unified Single-State RSI Loop Engine (`mindie-knowledge v0.13.13`)

1. **Single Authoritative `ExperimentLedger` Store**:
   - Eliminates the separate `rsi-loop-state.json` state file and consolidates all RSI round tracking onto `ExperimentLedger` (`graded/experiment_ledger.py`), with `RSILoopEngine` (`graded/rsi_loop.py`) acting as a stateless coordinator exposing the three `orient` / `propose` / `verdict` primitives.
   - Preserves baseline reconciliation across `superseded` verdicts, maintains round ordering when retrying older `record_id` entries, and recovers `refuted` records even when `bottleneck_summary` is omitted.
2. **Inline `active_rsi_session` in `knowledge_explore`**:
   - When an active RSI ledger exists in the workspace, `knowledge_explore` automatically attaches `active_rsi_session` (current round, `refuted_families`, and recommended next action), enabling zero-overhead transition from factor-graph exploration to hypothesis verification.

## 2. Higher Graded Retrieval Token Budgets & Superseded Service Retirement

1. **Higher Default Token Budgets for Complex Engineering Tasks (`graded/context_manager.py` / `graded/explore.py`)**:
   - `knowledge_explore` default `token_budget` raised from `12000` to **`24000`**;
   - `knowledge_query` default `token_budget` raised from `4000` to **`8000`**;
   - `knowledge_explain` default `token_budget` raised from `8000` to **`16000`**;
   - Maximum per-call `token_budget` ceiling (`MAX_TOKEN_BUDGET`) raised to **`64000`**.
2. **Stale `state=replaced` Service Retirement (`mindie-agent-codex#85`)**:
   - Validates and safely retires superseded `state=replaced` service owners and launch records (`service-launch.json`) in `loop/cli.py` and `loop/systemd_service.py` so stale replaced processes never block `service replace`.

## 4. Ascend 950DT (A5) 16-Trial Controlled CPU Contract RSI Auto-Promotion & C6 Distillation A/B Benchmark (`track-RSI-E2E-v4`)

Across 4 Ascend 950DT (A5)-themed controlled CPU tensor and ablation contract fixtures (`vllm-ascend-mla-prolog-rope-kvcache-fusion-rsi-zh`, `dsv4-sparse-mla-qli-fusion-rsi-zh`, `vllm-ascend-dspark-mtp-aclgraph-d2h-rsi-zh`, `triton-spatial-norm-dim-merge-rsi-zh`; `validation_scope="controlled_cpu_tensor_and_ablation_contract"`, not live NPU throughput/latency measurements) under single-variable parity (identical `task_digest`, `corpus_commit`, initial `corpus_view_sha256`, and shared `L1–L3` workflow guidance between `G2` and `G4`, with no differential prompt coaching) on **Codex (`gpt-6.1-sol xhigh`)** and **DSH (`deepseek-flash max`)**, with an independent artifact audit by **Codex `gpt-6-astra (max)`**:

- **Controlled CPU Contract Pass Rate**: Control `G2` (`MINDIE_DISABLE_RSI_EXPLORE=1`, physical `L4` isolation) achieved **`0 / 8 (0.0%)`** on the full scoring contract despite recording `3..8` distinct refuted candidate hashes (`35` total) in `logs/experiment-ledger.jsonl` (note: e.g., `codex/G2/mla-prolog` satisfied base tensor accuracy `max_abs_error=0.0` but scored `0.0` without the `L4` ablation contract), whereas Treatment `G4` (Auto-RSI + Stop-hook `graded-c6` distillation) achieved **`8 / 8 (100.0%)`** (**`+100.0 pp`** on the controlled contract).
- **Automatic `reuse -> explore` Promotion without Explicit `explore` Calls (`caller_initiated_explore=False`)**: All `8 / 8` `G4` trials triggered their first `explore` transition automatically from `requested_mode="reuse"` (`auto_switched_from_reuse=True` on first promotion and `caller_initiated_explore=False` throughout) after `3` distinct `candidate_sha256` refutations under the shared `L3` staged-verification workflow (no differential coaching between `G2` and `G4`, rather than zero procedural guidance).
- **Stop-Hook `graded-c6` Local Git Distillation**: All `8 / 8` `G4` trials completed `graded-c6` distillation, Gitleaks redaction, and local bare Git repository commit (`c6_distill_status="completed:applied"`).
- **Independent Audit Verdict & Methodological Qualifications (Codex `gpt-6-astra max`)**: All 5 narrowly specified artifact checks **PASS** (`G2/G4` parity, physical `G2` `L4` isolation, `8/8` `G4` first automatic `reuse -> explore` promotion, absence of cleartext private ablation identifiers in public tests, and `16/16` verifier replay + `8/8` local `graded-c6` Git commits), while explicitly qualifying that the benchmark demonstrates mechanism closure on controlled CPU contracts under shared `L3` workflow guidance (and noting that the raw v4 `dspark` verifier output recorded `full_candidate` prior to the strict 4-arm verifier hardening in `mindie-bench 0.4.7`) rather than unguided live Ascend 950DT speedup measurements.
