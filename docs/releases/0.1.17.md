# 0.1.17：历史 `n-1 -> n` 原生插件平滑自升级与在线活跃会话交接全覆盖修复

[English](0.1.17.en.md) · [产品组合](../../channels/0.1.json)

本补丁版本针对 `0.1.16` 宿主插件大减法（Great Subtraction）后存量旧版原生自更新器与尚未重启的在线宿主会话向新底座交接的边界（一揽子修复 [`mindie-agent#378`](https://github.com/mindie-agent/mindie-agent/issues/378)、[`#379`](https://github.com/mindie-agent/mindie-agent/issues/379)、[`#380`](https://github.com/mindie-agent/mindie-agent/issues/380)、[`#381`](https://github.com/mindie-agent/mindie-agent/issues/381)、[`#382`](https://github.com/mindie-agent/mindie-agent/issues/382)、[`#383`](https://github.com/mindie-agent/mindie-agent/issues/383)），系统性加固 `mindie-agent-codex`、`mindie-agent-cc`、`mindie-agent-kimi` 与 `mindie-agent-dsh` 的 `n-1 -> n` 在线平滑自升级与活跃会话交接兼容桩，并将薄宿主插件代码预算校准为 `<= 1,500` 行以兼顾可读性与架构克制。

## 核心变更与验证

- **Codex CLI `v0.1.34`–`v0.1.37 -> v0.1.39` 活跃会话热切流与跨平台构建加固（[`#379`](https://github.com/mindie-agent/mindie-agent/issues/379)–[`#383`](https://github.com/mindie-agent/mindie-agent/issues/383)）**：`mindie-agent-codex v0.1.39` 补齐轻量 `harness_update.py`、`runtime_call.py` 与 `admission_ops.py` 交接桩，消除切流后尚未重启的旧版常驻 MCP 进程与 `update_trigger._run` 后台维护线程报错；同时将 `bootstrap.py` 构建目录迁入短路径 `%TEMP%`（消除 Windows `MAX_PATH` 溢出）、移除强制 `http.sslBackend=schannel` 覆盖、修复 POSIX 虚拟环境软链保留逻辑与 `.whl` 组件下限继承，并在 `release_activation.py` 强制校验旧知识服务确认空闲退役。
- **Claude Code `v0.1.29 -> v0.1.31` 在线自升级与活跃前端交接修复（[`#378`](https://github.com/mindie-agent/mindie-agent/issues/378)）**：`mindie-agent-cc v0.1.31` 补齐标准库 `component_update.py`（支持保留更高组件下限或回退锁定基线）、`setup.py --source / --activate`（含 `operation.lock`、`component_source_commands` CAS 与确认退役门禁），以及面向存量未重启 `v0.1.29` 会话的 `bridge.py`、`mcp_server.py --once` 与 `release_update.py` 交接桩。
- **Kimi Code `v0.1.30 -> v0.1.32` 探针与独立启动器交接**：`mindie-agent-kimi v0.1.32` 补齐 `scripts/transcript.py` 转发桩，`mindie_launch.py` 从 `update/current.json` 原子元组统一解析解释器与 `scripts/`（兼容 `generations/<sha>` 与 `component-runtimes`），并支持历史计划任务的 `updater check|status` 调用。
- **DeepSeek Harness `v0.1.25 -> v0.1.27` 两阶段自升级与同意配置平滑迁移**：`mindie-agent-dsh v0.1.27` 在 `scripts/setup.py` 支持 `--python`、`--total-timeout`、`--component-manifest`、`--prepare-only`（准备阶段前置校验组件下限），使用不解引用叶子软链的解释器比对通过内置 `mindie-harness-seed.pyz` 预置现代底座，并将历史 `dsh/{config,mindie-consent,mindie-community}.json` 平滑迁移至规范路径；`storage_lifecycle_gate.py` 将 `THIN_HOST_PLUGIN_MAX_LOC` 校准为 `1,500` 行。
