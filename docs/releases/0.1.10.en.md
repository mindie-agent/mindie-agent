# 0.1.10: First-Time SSH Onboarding & Cross-Host Task Continuity

[中文](0.1.10.md) · [Product combination](../../channels/0.1.json)

This release packages the already-published runtime and plugin fixes together with the complete 15-repository `benchmark-manifest.json`, and moves publication-input completeness checks upstream into PR CI. The earlier `0.1.9` product candidate halted before creating a formal GitHub Release because that manifest was absent (its Git tag is preserved without retargeting); unchanged plugin artifacts and historical benchmark identities remain untouched.

Functionally, this patch fixes an issue where the public `remote_auth` interface rejected an SSH password already provided by the user in chat, and enforces the task-continuity contract—ensuring optional helper failures never block the primary engineering task—across all six native host plugins.

## Behavior changes

- **One-step reusable SSH onboarding**: Public `remote_auth(action="setup")` now accepts a one-time `password` input, installs the user's public key through the shared authentication helper, and verifies key-based access in a fresh child process. Ephemeral passwords are never written to config files, receipts, or persistent environment variables, and existing working SSH identities are reused automatically.
- **Isolate optional helper failures**: When knowledge retrieval, onboarding helpers, diagnostics, optional components, or local ledgers are unavailable, the Agent continues independent authorized work through native host capabilities while preserving the original goal, session identity, permissions, resource leases, and active background jobs.
- **Keep stdio MCP servers alive across request errors**: Google Antigravity and Tencent WorkBuddy return request-scoped admission or accounting errors without terminating the MCP process, keeping `ping`, tool discovery, and subsequent independent calls responsive. Antigravity also rejects replayed one-shot `bind` tokens so stale conversation identities are never inherited.
- **Decouple primary outcomes from local receipt writes**: Once remote authentication succeeds, a local profile-write error no longer flips the result into a failure (attaching a receipt warning instead). Unsaved profiles never mint a bogus `auth_ref` or mark a `coordinator` host as `ready`. Shared outcome classification distinguishes `completed`, `failed`, and uncertain external writes (`unknown`), requiring reconciliation before any retry.

## Validation scope

Two rounds of independent code review (`gpt-6-astra`, `reasoning_effort=max`) verified closure of all three confirmed P1 issues. Automated tests cover isolated unit regressions, public MCP schemas and dispatch boundaries, live stdio multi-request sequences, and SQLite receipts. Live OpenSSH acceptance passed across PowerShell 7, Windows PowerShell 5.1, and WSL2, and all six host plugins passed repository CI and exact-tag benchmark verification.

See the [task continuity audit](../audits/2026-11-06-task-continuity.md) and [first-time SSH contract audit](../audits/2026-11-06-ssh-auth-contract.md) for full evidence and scope boundaries (this control-plane patch does not claim new measurements on private user hosts, NPU inference throughput, or model accuracy).

Existing updaters discover the published components and plugins automatically. Candidate staging, active binding cutover, and host tool-catalog reload remain distinct lifecycle stages: running hosts pick up updated tool definitions at their natural reload or fresh-process boundary without interrupting active conversations.
