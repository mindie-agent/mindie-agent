# MindIE Agent 0.0.1 内测 Release

[English](0.0.1.en.md) · [返回文档索引](../README.md)

状态：主仓库、Codex 与 Claude Code 的普通 `v0.0.1` 已发布；三个配套组件 Release 已补齐并完成下载核对。本仓库提供统一发行记录。更新：2026-10-16。

产品版本固定为 `0.0.1`，Git tag 为 `v0.0.1`。这是面向内测用户的普通
GitHub Release，不使用 beta 后缀或 prerelease 标记。内测不豁免版本固定、
安装回读、数据保护和错误可见性。未发布的中间实现不承担多代兼容义务。

benchmark 独立推进，不是本次 Release 的前置条件。本次不宣称组件能够
提高任务质量、降低总成本或实现版本间的正向收益。

2026-10-15 用户新增 Windows WSL：首发验收现为 macOS、原生 Windows、
Windows WSL 各覆盖 Codex 和 Claude Code，共六个组合。WSL 沿用原生
Windows 的模型选择，但单独核对 Linux CLI、路径、进程/服务、首次和增量
采集以及生命周期。后文“四组合”是新增范围之前的历史记录，不能视为排除
WSL。原有成功证据继续保留，不重放旧失败或已付费回合。本轮运行时和入口
发生实质重构，六组合以新的合成任务补验受影响行为。

## 首发已知问题

2026-10-16 用户确认：Codex 子代理的取消传播缺口不阻塞 `0.0.1` 内测发布，
也不为它增加临时补偿功能。明确中断子代理后，正在执行的 MindIE 工具调用
可能收不到取消信号，本地调用进程或远端命令可能继续运行至结束；界面显示
`interrupted` 不代表该调用及其外部效果已经停止或回滚。

这条限制不改变主线程 Interrupt、Claude Code 标准取消及宿主退出清理的
既有验证结论。显式创建的持久远端 job 仍按原 job 生命周期管理，不因结束一次
等待调用而自动停止。原生失败与上游补充评论保留，不把接受限制记录为测试通过。
官方修复发布后，复用既有探针补验受影响边界并更新支持声明；当前不分发私有
Harness，不新增轮询、进程管理层、自动重试或任意业务时限。

## 设计原则 Review

依据同提交的[产品设计原则](../design-principles.md)，包括 Harness 兼容最高
版本、成功检查间隔 24 小时、异步准备和空闲短切换约束。此处是发布文档
的 review，不能代替各实现最终 diff 及六组合验收。

1. 总成本：复用原生市场、uv 和 OS 管理机制，删除重复更新编排；更新热路径不联网、不反复扫描安装，失败退避；benchmark 独立，不增加 beta 通道。
2. 封闭问题：版本读取、状态声明和候选检查限定在机械交付问题；实际收益不作机械保证。
3. 理解负担：用户只面对 `0.0.1`；内部安装标识与组件编号不形成新操作流程，正常更新和重载不重新授权。
4. 单一边界：共享函数负责兼容选择，原生安装器负责下载和记录，一份安装配置负责活动绑定；不增加第二版本权威。
5. Skill 信息性：本次未增加强制 Skill 流程，发布文档不要求每个业务任务执行检查。
6. 知识参考性：公开发布、索引和检索不等于正确性或收益认证；限制保留。
7. 按需介入：验证仅在已授权的隔离合成任务范围启用贡献，不扩大到用户真实
   项目；不运行 benchmark 模型调用，不把本地模拟投递视为公开写入授权。
8. 机制与成果复用：先验证旧缓存、短 Hook 和平台所有权的确证缺口，再补稳定入口和最小 helper；删除未发布多代兼容及迁移链，Release 排序仅用于兼容选择；保留未变化的有效证据，不以历史通过冒充新组合通过。
9. 错误可见：缺失/错误候选版本拒绝打包；不同已发布格式拒绝重置；
   执行结果不确定仍保留。原生、CI、本地发布、公开送达与未完成门禁分列，
   已完成结果不因次级诊断或清理失败而被覆盖。
