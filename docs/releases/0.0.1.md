# MindIE Agent `0.0.1` 版本发布记录

[English](0.0.1.en.md) · [返回文档中心](../README.md)

`0.0.1` 是 MindIE Agent 的首个正式内测发行版（Git Tag 为 `v0.0.1`，在 GitHub Releases 上均为 `draft=false`、`prerelease=false` 的正式 Release）。本文汇总本次发布的配套组件映射、支持的宿主与操作系统矩阵、已验证的核心能力以及已知宿主限制。

> **说明**：开发与实机验收过程中的详细测试批次记录已归档至工程档案库，本文仅保留对用户与维护者有价值的正式发行信息。

## 3. 已验证的核心能力

1. **原生安装与 24 小时后台无感更新**：
   - 首次安装固定不可变 `v0.0.1` 标签；距上次成功检查超过 24 小时后，日常使用异步匹配当前宿主的最高兼容正式版，在锁外构建环境并趁空闲时原子切换，全程保留既有用户授权。
2. **远端昇腾 NPU 执行与本地经验闭环**：
   - 六个环境均通过 `remote-dev` 完成了真实的远端昇腾服务器命令执行、文件读取与状态检查，并自动完成公开对话提取、Gitleaks + 隐私规则脱敏、小模型导航索引生成及本地混合检索验证。
3. **社区知识贡献、Bot 审核与增量同步**：
   - 验证了任务知识包自动发起公开 PR、Grok Bot 安全合规审核并合入 [`knowledge-vllm-ascend`](https://github.com/mindie-agent/knowledge-vllm-ascend)、新客户端增量同步（661 个任务包）以及 `helpful` 反馈闭环。
4. **有界本地诊断与可选故障上报**：
   - 验证了本地结构化诊断日志轮转、跨任务故障指纹去重以及独立授权下的 GitHub Issue 自动故障上报。
5. **Kimi Code 原生接入与验收驱动修复**：
   - 在 kimi CLI `2.1.1` 与 `2.2.0` 上验证了统一入口双形态身份核验（顶层与嵌套 skill 激活均绑定，纯文本/无头/外部同名 skill 一律拒绝）、`knowledge v0.11.0` 新摘要协议的完整移植（`--identity` 指纹握手 + 严格结果信封，无兜底摘要、计费不确定不重试）、以及 `uv` 秒级构建的后台原子更新。
   - 验收驱动修复并合入：updater 构建超时改 `uv` 路径并新增诚实 `deadline` 类目、授权配置根锚定 profile 不随生成分裂、systemd 搁浅回执退役与 SIGTERM 终态回执（knowledge v0.11.3）、破损素材退避与可见终止、Windows 共享重试、stock Ubuntu `uv venv` 兜底、`service_launch_context` 跨启动边界传递摘要 worker 依赖。
6. **DeepSeek Harness 原生接入（补录验收）**：
   - 在 macOS 27.0.1 arm64 + DSH `0.2.0-rc.2` 上验证了 Host 行组合（不覆盖任何内置行/预设）、`/mindie-agent` Skill 发现与模型隐藏策略、`knowledge_query` / `knowledge_explain` / `knowledge_sync` 的真实 MCP 调用，以及官方 `remote-dev` MCP 工具注册与可见失败路径。

## 4. `0.0.1` 已知限制说明

- **OpenAI Codex CLI 子代理（Subagent）取消信号缺口**：
  - 在 OpenAI Codex CLI 中，当主会话被中断或显式中断子代理（`spawn_agent`）时，Codex 上游目前仅中断主线程等待句柄，尚未向子代理正在执行的 MCP 工具调用传递取消信号，可能导致子代理拉起的本地辅助进程或单次远端命令继续运行直至自然结束（主线程直接调用的工具取消以及 Claude Code 取消均已正常工作）。
  - MindIE Agent 如实记录该上游限制，不在插件内引入高侵入性的私有杀进程守护或武断超时；通过 `remote-dev` 启动的远端持久后台作业始终可通过 `job_cancel` 显式停止。我们已在 [openai/codex#26956](https://github.com/openai/codex/issues/26956#issuecomment-6205886409) 附上最小复现与修复分析，待上游正式发布修复后更新支持区间。
- **Kimi Code 宿主交互边界**：
  - 无头 `kimi -p` 与 ACP 通道不产生原生 slash 记录；变更类操作（`sharing-*`、`deactivate`、`recover`、`reporting-*`）仅 TUI 可达（`/mindie-agent:<op>` 或已绑定会话）。kimi prompt 模式不上报用量计数，付费摘要调用一律记账为 `model_calls=1` 且 `usage_known=false`，绝不记 0。GBK 代码页主机上 ACP 流的中文显示存在乱码（`wire.jsonl` 正文无损，采集不受影响）。
  - Linux/WSL 后台更新调度如实报告为手动档（不注册计划任务）；Linux 服务要求 `systemd >= 254` 用户管理器。知识服务在一次慢启动中的就绪探针可能瞬时上报 `unknown` 并如实报错，下一次按需调用即恢复（不影响数据与已入队采集）。
  - 升级路径说明：重装（重复执行 `setup.py`）不会刷新已保留的 bootstrap generation，既有安装如需获取适配器脚本修复，应通过 24 小时后台更新通道（或文档化的重建步骤）完成，而非简单重装。
- **评测与宿主范围边界**：
  - 端到端业务提效基准评测（Benchmark）作为独立事项推进，`0.0.1` 不预先宣称量化提效比例。
