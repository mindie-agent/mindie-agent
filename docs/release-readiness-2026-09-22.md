# 首版使用流程收敛

2026-09-22。以下为本轮已授权的实施范围，不是验收通过声明。
遵守[九条原则](design-principles.md)，复用既有配置、维护机会和真实证据。

## 运行时修改

独立故障上报器随插件维护更新。仅当独立上报授权仍开启、现有服务实际健康，
且目标 diagnostics 版本更高时交接；未配置、关闭或异常停止时不启动。
同版本同内容不重启，同版本不同内容明确报告冲突，不猜测哪个适配器更新。
低版本适配器不降级共享上报器。复用已有互斥和持久状态，单个目标交接失败
保留结果，后续定时检查不反复尝试；显式 ensure 才可恢复。上报队列、授权版本、
发送预算和回执不因更新重置。普通离线日志维护不包含启停行为。

维护使用调用方剩余时间，不能在进入上报器后重新获得完整超时。单次维护最多
75 秒；不足以保留交接、回滚及退出时间时跳过服务变更。交接失败后只做一次
有限回滚，保留实际失败动作和系统返回码。服务版本指针在新服务健康回读后提交；
提交后的结果记录写入失败要报告降级，不能把仍在运行的新版本误称为已回滚。
等待锁或系统命令期间发生关闭、重新授权时，后续启动必须重新核对原授权版本。

取消更新调度先读取实际系统状态，再执行一次取消并核对结果。任务已不存在
可幂等成功，其他失败不能伪报 unscheduled，也不能继续删掉仍被使用的启动材料。
卸载某个适配器不撤销其他适配器共享的故障上报设置或服务。

删除旧 Grok CLI 自动诊断和中央 bot 入口及专用依赖，不保留旧命令别名。
纯故障上报仍通过独立授权和确定性字段生成 Issue，不调用模型。
外部 Grok Bot 软件继续负责知识仓库内容审核与合入。

## 交付与验收

| 工作 | 完成依据 |
| --- | --- |
| 三端安装说明 | 从持久安装、首次选择到状态、更新、关闭和宿主卸载均有可执行短路径；明确共享服务边界 |
| 上报服务更新 | 真实 macOS 服务版本交接、无变化、低版本、关闭、已停止、失败可见及恢复结果；不以模拟系统命令替代 |
| 取消调度 | 真实系统成功、缺失和失败路径，以及保留启动材料的结果 |
| 原生上报入口 | Codex Luna/max、Kimi K3/max、Claude Code 既有 DSV4/high 原生开启、执行返回命令、就绪状态和关闭；跨端可见同一独立设置 |
| 知识贡献与复用 | 一次全新的实际 Kimi 工作，经原生 Stop、整理和自动 PR；观察 Bot 事件合入与另一新任务的具体使用 |
| 内容质量 | 经验仅复述已有过程和现象；不编造失败、因果或未提及内容，无有用新增内容可返回零条 |

模型开发使用 Kimi K3/max 与 Grok 4.7/Extra High（CLI 参数为 xhigh）；
这与原生宿主验收模型分别记录。Hook、MCP、整理和发布等封闭操作保留各自的
时间、输出及重试边界，不给开放的业务开发统一设置总截止期限。长任务使用宿主
支持的原生自动审批；正常修改、重编译和复测不属于失败采集的自动重放。
采集整理的同一失败输入不自动重放，未知写入先核对；不自动重启已退出的业务
模型。任务结束后清理自有服务和进程，阶段性观察不终止仍在工作的原生任务。
开发检查、原生接线、实际业务、版本安装和自动投递的结论分别保留。

Windows 由用户后续在专门机器推进。旧业务 Skills、profiling、自动 Skill 提炼及
新领域/新 Harness 扩展保持暂缓。此前已修复问题的历史记录保留，并链接到后续
完成证据，不能因旧文档未更新而再次当作产品缺陷开发。
