# 经验组件测试、验收与迭代合同

日期：2026-10-04。这是实施和比较方案的可执行规格，不是已经获得的质量结论。初始合成探针见[研究阶段审查](knowledge-experience-review-2026-10-04.md)；后续已取得的真实材料索引、本地检索和独立消费者结果见[实施证据](knowledge-review-2026-10-04/evidence/implementation-review.md)。两者都不能代替尚未完成的原生与远端完整链路验收。

## 1. 测什么，不混淆什么

| 层 | 核心断言 | 不能推出 |
| --- | --- | --- |
| 机械处理 | 授权、边界、去重、脱敏、状态转移、版本、外部副作用符合合同 | 摘要语义有用 |
| 输入覆盖 | 模型看到哪些事实/纠正、没看到哪些区段 | 看到了就一定保留；摘要没看到就一定搜不到 |
| 真实摘要 | 实际指定模型生成的卡片忠实、有用、花费可见 | 已完成原生事件到公共发布 |
| 实际检索 | 用现有 Store.query 在固定语料测命中、排序、适用性判断 | 当前任务真的少走弯路 |
| 原生完整链路 | 原生 Hook、模型、GitHub、Bot、独立缓存各有匹配回执 | 所有平台、所有任务普遍有效 |
| 实际帮助 | 独立任务成功/返工/调查/阅读/总成本改善 | 单次成功是普遍因果证明 |

每项分别记 pass / fail / not_run / unknown，不设一个混合总绿灯。模型不可用是该层验收失败或受阻，不由 Python stub 代替。更多单元测试不能“补足”缺失的真实模型实验。

## 2. 最小回归矩阵

| ID | 场景 | 必须观察的结果 | 优先级 |
| --- | --- | --- | --- |
| A01 | 未激活任务收到 Hook | 不读记录、不建采集工作、不调模型 | 阻断 |
| A02 | 安装授权已有，重启/升级后重新激活 | 不重复授权；当前任务身份重新正确绑定 | 阻断 |
| A03 | 激活但贡献关闭 | 可查公共内容；零采集/脱敏/模型/上传 | 阻断 |
| A04 | 关闭后恢复 | 不回填关闭区段、不重置失败预算 | 阻断 |
| A05 | 历史导入未明确请求、请求后重复导入 | 前者无扫描；后者不重建等价条目，失败阶段可显式恢复 | 阻断 |
| C01 | 重复事件、Fork继承、子代理重复材料 | 同一来源不变成多次贡献/独立成功 | 阻断 |
| C02 | 读取后崩溃、事务前后崩溃 | 原子保存正文+边界；不会跳过未保存或追加两次 | 阻断 |
| C03 | 文件替换/截断/坏 JSON/超长单条消息 | 明确原因与受影响范围；不假成功或悄悄跳过 | 阻断 |
| P01 | 凭据跨行、跨页、跨消息、跨通知、跨重启 | 模型输入及出站均无合成尾部 canary；边界状态正确 | 阻断 |
| P02 | 重叠敏感片段、未闭合私钥、脱敏占位符 | union覆盖；占位符幂等；来源伪占位符不跳检 | 阻断 |
| P03 | 私有业务文字不含常见秘密模式 | 规则扫描不能标成完整语义隐私通过；按批准范围处理 | 阻断 |
| S01 | 缺少模型、拒绝、超时、坏输出 | 材料保留，摘要失败/未知可见，新批次不发摘录 | 阻断 |
| S02 | 模型成功后扫描器失败 | 只重做本地检查，调用数和用量不丢失、不再调模型 | 阻断 |
| S03 | 模型执行中进程死、重启 | 不把未知付费调用重置为未调用，预算持久 | 阻断 |
| S04 | 输出到达时正文/授权已变化 | CAS拒绝旧覆盖；处理新版或取消，不能复活已撤授权 | 阻断 |
| S05 | 只改 worker提示词/模型，路径不变 | 旧摘要缓存失效，有明确版本依据 | 必须 |
| S06 | 同输入同策略重复检查/发布失败 | 成功摘要复用，发布恢复不重跑模型 | 必须 |
| S07 | 关键发现、纠正或验证边界在中间 | 记录输入覆盖；真实摘要/实际检索/选读分开评分 | 质量 |
| S08 | 结果仍失败、只是计划、仅局部测试 | 不升级成成功/已执行/全面验证 | 质量阻断 |
| G01 | 发布成功响应丢失 | 读回原操作，不重复建PR；未知未解时不新写 | 阻断 |
| G02 | 开放PR有后续材料、合并后有新材料 | 分别更新原PR/建后续PR，无冗余近似贡献 | 必须 |
| G03 | Bot/main改正文后仍有本地观察 | 远端权威保留；摘要重新绑定；增量可继续导出 | 阻断 |
| G04 | 模型/正文/PR含恶意指令或越界文件 | 当数据处理；不能改workflow、执行工具或越出白名单 | 阻断 |
| G05 | 同head重复事件、CI晚完成、新head | 审查按head复用；新head重核；不会被bot自身写入循环触发 | 必须 |
| D01 | 同步断网、坏包、索引未就绪 | 旧缓存及陈旧状态明确；没有缓存时不返回假空结果 | 阻断 |
| D02 | 主线退役、旧revision正文清理 | 普通查询退出；旧引用明确失效，不读到新正文 | 阻断 |
| D03 | 发布确认后清理 PermissionError | 发布仍成功，清理单独失败；保留真实残留计数 | 阻断 |
| F01 | 纯反馈、改票、同根任务重复票、旧revision | 无正文也可形成批次；去重/更正正确；不转嫁给新版 | 必须 |
| R01 | 长记录、多次追加、多次改摘要 | 测累计读取/扫描/索引/写盘/RSS；不以单次输入上限代表总成本 | 性能 |
| R02 | 长正文读分页、中文和代码混合查询 | 续读完整，失败非空结果；测真正query，不只测关键词包含 | 必须 |

阻断是本次交付门槛，不是为用户增加运行时审批。测试在独立 HOME、状态目录和已固定依赖中运行；不得误写生产 updater/配置，不使用真实凭据或用户 transcript。

## 3. 公平比较四种摘要路线

| 组 | 输入/更新方法 | 核心风险 |
| --- | --- | --- |
| B0 全文一次小模型 | 固定最终材料，一次生成标题摘要 | 全文仍贵/超窗；完整输入也可能遗漏；不当标准答案 |
| B1 现有首尾 | `head-tail/1`，当前12KiB及原比例 | 中段唯一发现和撤回没进入输入 |
| B2 结构化抽样 | 与B1同预算；完整消息、中段分布、纠正/现象候选，去重且保持顺序 | 启发式偏差、缺少触发词的更正、代码噪声挤占 |
| B3 小模型增量摘要 | 每批新增材料+有界当前头部；不强制最终全量合并 | 多次固定开销、摘要漂移、遗忘旧边界、晚期纠错失败 |

新增框架的默认 pipeline 可作 B4，但必须计入全部观察、提炼、tag、反思、embedding、检索、压缩、重试。只调用其一个模块就以该模块实际配置参赛，不能把关闭后的能力作为收益宣传。

固定：来源快照、同一模型实际标识与推理配置、最终输出目标、价格口径、检索语料/查询、评分规则。既比较最终质量/累计成本，也比较相同整任务预算内的完成范围。单次价格和多次总价不能混比；全文一次与每轮重发累计全文不是同一基线。

每组记录所有覆盖区间和失去的关联。超窗、预算耗尽、请求失败和模型不支持分别保留为失败样例，不从分母删除，不偷偷切换模型。不承诺以固定12KiB覆盖任意长度材料中的所有有用信息。

## 4. 样本与评分

初步复用既有10类合成样例：短任务、中段发现、中段纠正、失败方法、局部验证、多主题、Unicode、尾部正向对照、晚期撤回、用户纠正助手。fixture中的技术名均为合成；不把它们当真实 NPU 经验。

新增变换：改变关键句位置、长度、噪声密度、同义问法、版本/拓扑、原先错误结论的措辞；其中只有工具输出含结论的样例应判公开消息证据不足。按任务家族划分调试集和冻结评估集，不能把同一模板的小改写随机分到两边就声称独立留出。

不默认一次运行大评测。先少量代表样本确认模型通道、计量及严重错误，再按已设实验预算扩大和复跑。样本数、重复次数属于实验设计，不固化为产品配额。真实历史只在当前任务明确授权该处理范围后，在本地脱敏使用；不得把先前某次公开贡献的授权外推到全部历史或发送给外部框架。

评分分四部分：

1. **忠实性**：归属、事实/猜测、计划/执行、失败/成功、局部/全面验证、撤回关系。关键词存在但含义反转仍是严重错误。
2. **检索卡有用性**：盲评者只看标题/摘要/命中片段，能否挑出相关记录，能否知道下一步需要读什么。
3. **实际检索**：固定 corpus 跑 `Store.query`，评 Recall@5、MRR、版本/条件误匹配；同时报告分场景结果与失败样本。所有策略保持正文相同，避免把正文改变收益算到摘要。
4. **消费帮助**：另一任务只从公共结果读经验，记录调查步骤、阅读token、耗时、成功范围和返工。用户声明“有用”可作信号，不替代独立事实记录。

人工小样本盲评为主，确定性断言检查版本、哨兵、语法与覆盖；不强制再调用强模型做裁判。如果使用模型评分，记录它的版本、费用、分歧与人工抽检，评分不能自动认证经验真伪。

建议首次发布门槛：关键纠正/归属/假成功的冻结哨兵零严重反转；所有机制阻断项通过；检索卡与实际检索不劣于可用基线，并有明确累计成本收益。可以在预试后设定诸如关键主题覆盖≥80%、Recall@5相对全文基线下降≤5个百分点、用量下降≥50%的候选数值，**但这些尚非用户要求或已证明合适的门槛**。正式比较前固定门槛和样本量，不能看到结果后改标准；基线本身很差不能成为宽松通过的理由。

## 5. 成本口径

每次真实调用记录：request/attempt ID、body digest、策略/提示词/适配器版本、实际模型、缓存输入/非缓存输入/输出及可得推理token、开始/结束、provider回执、completed/failed/unknown、是否复用、价格日期/币种。缺失数值为null并说明原因。

总模型费用为所有调用已知计费量乘当时价格之和；订阅额度、隐藏推理计费、网络失败造成的未知收费要单独说明。不得用请求字节比例直接折算费用，也不得漏掉失败/重复调用。

另量：Hook返回延迟；后台读取/扫描字节；处理CPU/RSS；SQLite+WAL、暂存、索引和Git对象总量；出站/同步字节；Grok消耗；消费者读取量。每项附设备、版本、语料规模、重复次数和离散程度。

扩展曲线比较相同最终正文经历1/10/100次追加，区分“正文大小增加”与“历史副本增加”；摘要只更新头部也需观察全文索引代价。噪声倍率改变时，不预先宣称处理成本不增长。

## 6. 一条真实验收链

生产安装前，在两套独立客户端状态中完成：

1. 固定组件组合、策略、可信内容校验器和预期公开测试仓库/范围；复用已有授权，不更改无关配置。
2. 贡献者会话显式激活。用合成公开任务正常结束，观察真实Hook交接、摘要实际模型、费用和状态；不用手工写数据库模拟采集完成。
3. 回读PR当前head与出站文件。区分创建、Bot收到事件、Bot审查、CI、合并；定时补查与事件到达各记一项。
4. 消费者用完全独立数据库与缓存，只同步main确定提交，按预先固定问题query/explain；不能继承贡献者私有草稿。
5. 贡献者追加一条撤回/更正；让发布侧对原条目作一次允许的正文修改，验证本地后续观察不覆盖远端、摘要重新绑定、消费者读到新版。
6. 注入一次受测失败与一次停用；确认无重复模型、无重复发布、错误对调用者可见。确认当前正文/暂存/索引清理后不积累旧全文。

只承认实际执行的平台和Harness范围。Windows没跑就未验收；当前会话旧Hook仍在运行也不算新版本Hook通过。真实故障实验使用隔离合成材料，不在用户正在工作的任务中制造失败。

## 7. 可复现的本轮反例

已有的 organizer 和 delivery evidence 含脚本、结果及源码SHA256。新增 `evidence/input/probe_input.py` 只调用初始研究快照的真实选择器、读取明确标记synthetic的fixture，输出覆盖计数；没有LLM调用，报告不会输出长正文。下例的 `KNOWLEDGE_RESEARCH_ROOT` 指该初始源码工作副本，`SUMMARY_EVALUATION_ROOT` 指持有记录中 SHA256 对应合成 fixture 的目录；公开证据不包含本机绝对路径。

```sh
PYTHONDONTWRITEBYTECODE=1 python3 docs/knowledge-review-2026-10-04/evidence/input/probe_input.py \
  --core "$KNOWLEDGE_RESEARCH_ROOT" \
  --fixtures "$SUMMARY_EVALUATION_ROOT/fixtures.json" \
  --output /tmp/mindie-input-probe.json
```

这些是设计依据的反例探针，不是产品新测试框架。后续修复时，应将相关最小合成场景放进所属组件已有测试目录；根架构仓不接管运行时。

## 8. 每次迭代怎样收敛

先按问题类型定位：输入没看到 → 选择策略；看到但写反 → 模型/提示；卡片差但全文可搜 → 摘要/命中片段；库里有但找不到 → 检索；处理成功却没发 → 状态与发布；用量未知 → 计量。不要每次失败都扩大正文整理任务。

迭代只改一个主要变量，并把失败样例加入固定回归。保留有效结果，避免全量重算历史语料。版本、模型、提示词或schema变化应能定位到受影响的条目/策略；接口兼容性按变化测试，不强制重做无关实机实验。

若结构化抽样不改善卡片，撤回；若增量摘要更贵或纠错更差，不采用；若外部框架引入的适配/生命周期代码多于替代代码，又没有质量优势，不集成。反过来，若外部模块显著减少维护并通过同一合同，应删除被替代的自有实现，避免双栈永久运行。
